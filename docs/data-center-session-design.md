# 数据中心：安全调查与员工 Agent 行为分析设计

日期：2026-10-07

状态：第一版已开发并部署至 `https://www.chuhaijian.com/model-data`，2026-10-08 完成上线验收。以下包含产品目标与后续扩展方向，首版范围见下。

### 第一版实现范围

- 平台保留的 AppLens 上下文/已捕获请求、SessionLens Codex/WorkBuddy 源事件，完整正文可检索；不把未上报的终端活动算入覆盖。
- 关键词、字段组合查询及设备、Agent、来源、行为、内容位置、时间筛选；稳定翻页，不冻结采集。
- 调查详情显示观察事实、上传账号、设备、相关用户轮次、工具/函数/程序、完整参数和返回、实际采集依据及缺口。原文以完整来源身份定位，避免设备别名和重复编号串线。
- 自然语言调查经登录用户明确确认后，调用现有中转进行检索词规划、证据分析和复核。目前限一台所选设备、最多12条命中和24个相关片段，不能据此声称全局语义调查或全部事件数量。
- 普通搜索和详情不调用模型。平台原文不新增脱敏；发往既有中转的选中片段沿用既有凭据遮盖。
- 尚未接入真实员工身份，也未实现全局多轮任务归属、统一事件处置和自动复测闭环。原记录支持的关联与推断候选分别展示。

### 搜索结果与记录画像（2026-10-08）

- 搜索卡保留短摘要：发生时间、动作或目标、返回中的事实；上报机器、Agent、采集器固定显示。调用参数、提示词和返回摘要来自保留记录，不用固定演示任务填充结果。
- 点击“查看完整信息”打开记录画像。先给结果、资产和用户需求，再展示完整调用参数/提示词、可读返回、按时间排列的关联记录和上下文材料。原始返回、来源字段及完整 JSON 默认折叠。
- 嵌套工具的实际名称与外层执行器分别索引。例如 `DeferExecuteTool` 的 `toolName=VideoGen` 可用 `tool="VideoGen"` 查询，外层可用 `executor="DeferExecuteTool"` 查询。
- `domain="wttr.in"` 仍表示域名在任意保留内容中出现；新增 `target_domain="wttr.in"` 仅匹配显式工具请求目标或捕获的 HTTP 目的地主机。`target_ip` 同理。一个命令中的多个目标都保留；引用头、代理、请求正文和 URL 查询参数中的另一个域名不算目标主机。
- 工具状态、命令退出码和产物符合需求是不同概念。记录到退出码 0 不自动意味着 HTTP 200；工具返回 completed 不自动意味着视频已验收。
- 天气等结构化返回按实际字段呈现；`head -c` 截断或不完整 JSON 保留可独立解码的完整字段，并说明截取情况。完整“已采集返回”不是未采到的服务端完整响应。
- 画像中的连接由同一账号、物理设备、Agent、源会话内的唯一标识支撑。原始父消息可连接前后记录；另一次用户提问形成边界。重复父标识、多个用户共享轮次标识均不能强行确认归属。
- 最多展开 24 条关联记录、8 条同会话邻近候选；邻近候选默认折叠。关联内容每条上限 60,000 字符，达到上限显示截取与原文入口；当前选中记录的原文完整保留。该范围不宣称已还原完整业务任务或跨采集器链路。
- 结果摘要存入可重建索引，搜索仅对当前页做有范围的调用/返回配对；不会为每个结果展开整个画像。详情按需读取原始来源。

### Skill、MCP 独立对象与使用排行（2026-10-08）

数据中心搜索新增全部记录、工具、Skill、MCP 对象范围。MCP 不再依赖普通正文搜索：以可确认的服务名、方法名与调用方式组织；`mcp="cua_repl"`、`mcp_method="js"` 可组合查询。Skill 使用 `skill="agent-browser"` 查询，实际加载与说明读取分开标识。普通文本中出现名称、说明列表、安装配置和脚本写入不作为调用。

使用排行放在独立页面 `/model-data/rankings`，由数据中心入口进入，分为工具、Skill、MCP 三类。搜索页不堆放排行榜，也不自动请求排行接口。排行使用与搜索相同的设备、Agent、采集器与时间范围，默认按已采集活动记录数排序，显示设备数、上传账号数、源会话数及最近时间。源会话数量不改称任务数量，上传账号不冒充实际员工身份。

工具排行只计具名工具调用，不把工具返回重复计数。Skill 分列加载次数和说明读取次数，说明读取不宣称已启用。MCP 以服务聚合，方法可继续查看，直接调用与 Bash 包装调用分别统计。Shell 命令能证明记录了调用意图；退出码 0 不能证明服务处理成功。无法识别服务身份的内置工具不硬归为 MCP。

点击排行名称或方法带对象及准确字段条件返回搜索，并保留设备、Agent、采集器、时间范围。用户再点击具体记录核对完整参数、返回、机器和任务关联依据。排行只返回聚合元信息，不把全部原始内容发到浏览器，不调用模型；接口沿用现有公开数据中心权限。

统计基于可重建索引与规范设备身份去重，对名称相同但来源不同的工具保留 Agent 来源信息。分页快照分别绑定搜索和排行的查询范围；新上报数据通过刷新进入，旧快照不被当成固定采集状态。

## 1. 产品分工与用户目标

| 产品/模块 | 主要使用视角 | 优先回答的问题 |
| --- | --- | --- |
| SessionLens | 用户理解自己的业务任务、监督与追溯 | 当时要做什么、Agent 怎么完成、调用了什么、为什么这样做 |
| AgentPair 数据中心 | 安全人员、公司管理者调查安全事件和员工 Agent 行为 | 发生了什么、涉及谁和什么资产、资料流向哪里、证据与影响范围是什么 |
| 交互安全审计 | 已发现风险的核对与处置 | 风险是否成立、危害是什么、交给谁处理、修复后是否仍出现 |

数据中心优先按安全调查问题组织搜索结果。用户输入问题、关键词、工具名、函数名、文件名或地址后，应当得到：

1. 已观察到的行为或安全线索，以及具体命中内容。
2. 涉及的账号、已确认人员、设备、Agent、资料和目的地。
3. 用户发布了什么需求，相关行为由用户明确提供、Agent 自动带入还是工具执行产生。
4. 内容出现在哪个阶段：用户输入、历史/背景、工具参数、工具返回、模型请求或交付。
5. 哪些连接有直接证据、哪些是内容关联、哪些缺失，影响范围如何计数。
6. 是否需要继续取证、形成风险事件或交给处置人员；是否有已复测的结果。

完整 Session 和多轮任务是调查的证据组织基础。它们解释行为的背景和来源，不占据安全搜索结果的首要位置。无法确认任务归属的记录仍然可以搜索、调查，不能因此被隐藏。

### 调查问题示例

- 哪些已采模型请求包含服务器凭据，涉及哪些设备和账号？
- 这段代码或这份客户资料出现在什么输入中，发送目的地是什么？
- 访问这个地址的记录有哪些，属于什么任务、哪个工具调用？
- 某台设备近期调用过哪些 MCP 函数，参数和结果是什么？
- 这些动作是否与用户当时的需求相关，有没有重复携带旧背景？
- 同一份敏感信息是否出现在多个请求中，修复后还有没有出现？

具体人员归属、是否违反公司政策、是否超出授权和是否造成实际损失分别需要相应证据；不能用一项命中替代所有判断。

## 2. 四种东西必须分清

| 对象 | 含义 | 不能混用 |
| --- | --- | --- |
| 源 Session | Agent 保存的一段会话容器 | 一个 Session 可以有多个任务 |
| 用户任务 | 一项持续的目标及其要求变化 | “好、做、继续”通常不是完整目标，要结合前后需求 |
| 用户沟通轮次 | 一次用户发言及相应执行、回复记录 | 一轮沟通可能包含多次模型请求 |
| 模型请求 | 一次已记录的 Agent 到模型交互 | 工具调用次数、回复条数不能代替模型请求次数 |

任务中的“原始需求、补充要求、确认执行、修改要求、暂停和恢复”保留各自发言，不用最终摘要覆盖历史。每个执行动作应指向当时有效的要求版本。

同一个源 Session 中先查天气、再生成视频，可以分成两个任务。视频任务里的修改、确认和重试可以属于同一任务。恢复旧任务时，需要保留恢复依据。

## 3. 把内容组织成有关系的对象

| 对象 | 默认给用户看的内容 | 可展开的证据 |
| --- | --- | --- |
| 需求与讨论 | 原始目标、补充内容、当时有效的要求 | 用户原话、关联理由、前后轮次 |
| 模型输入 | 本次提问、历史对话、背景、文件节选、工具结果等材料 | 输入块原文、角色、位置、来源记录 |
| 输出与指示 | 已记录的回复、思路、工具调用指示 | 原文及来源；Agent 日志里的回复与已捕获模型响应分别标注 |
| 工具调用 | 工具/函数名称、动作、关键参数 | 完整参数、调用标识、执行命令 |
| 工具返回 | 成功/失败/待确认、主要结果、返回的文件或链接 | 完整返回、错误、退出状态等已采字段 |
| 资料与产物 | 文件、代码、网页内容、视频等在过程中的用途 | 路径、地址、内容、生成/读取证据 |
| HTTP 记录 | 已采请求的目的地和正文，与哪个过程相关 | 已捕获字段的原文；缺失字段明确显示未采集 |

每个内容对象可以有多种用途。例如，同一份工具返回可以作为后续模型输入，也可以成为最终交付依据。关系保留到具体出现的位置，不只保存一个全局名称。

上下文分类采用已有角色、字段和明确的内容边界；解释来源时要有对应证据。标为“记忆”的内容不自动意味着来自云端；正文里提到文件名不意味着读取了该文件。

### 工具、函数和程序分别展示

以下是结构示例，不是一次真实天气任务的证据：

> 工具：Bash → 执行程序：curl → 参数：具体 URL → 返回：网页或 JSON 内容。

如果记录来自 MCP，则展示实际服务及函数名称；如果来自命令执行，则展示命令与程序。代码中定义或提到某个函数，和实际调用这个函数分开索引。

对于脚本、管道和 shell 命令，解析结果是辅助解释，原命令始终可查看。不能仅从命令文本推断每个子程序实际运行成功。

## 4. 关系比孤立字段更重要

需要保存的核心关系：

- 哪次用户发言提出、补充、确认或修改了这项需求。
- 哪些记录属于这轮用户沟通。
- 哪些材料出现在这份模型输入的哪个位置。
- 哪次已记录的模型输出包含了这条工具调用指示。
- 哪条工具返回对应哪次调用。
- 哪份工具返回出现在后续哪份模型输入里。
- 哪些文件、链接或回复构成交付，哪些已有独立核验。
- 哪个已确认人员或账号与行为有关，身份依据是什么。
- 同一份资料在多少个独立请求、任务和设备中出现，如何避免重复记录计数。
- 哪些证据支持同一个安全事件，哪些行为需要分别调查。

关系有三种表达：

| 表达 | 需要的依据 | 用户看到什么 |
| --- | --- | --- |
| 原记录关联 | 同一范围内有效且唯一的调用、请求、轮次或父消息标识，或明确的内容位置证据 | “对应这次调用”“该内容出现在这份输入” |
| 内容关联 | 前后需求、执行及内容支持，经过引用与冲突校验 | “根据前后内容关联”，附具体理由 |
| 待确认 | 标识缺失、重复、内容截断或存在多个可能归属 | 缺口和候选，不画成已确认连接 |

时间帮助排序。同一个 IP、域名、关键词、时间段或 Session 标识不能单独证明任务归属或执行因果。

账号、规范设备身份、Agent 和标识的来源范围共同约束关联。设备名称相同不能直接合并；不同应用的同名编号不能直接连接。跨源 Session 的同任务关系需要另行核对，现有代码没有完整实现这一能力。

上传账号、设备归属账号和实际操作员工分别保存。当前只有上传归属时，展示该账号和设备，并标注“操作人员未确认”；不能直接把上传账号当成员工身份。将来可接入企业身份与终端登录映射，新增身份关系仍需保留来源和有效时间。

## 5. 一次任务展示为循环，而不是单次流水

以下是页面结构示例，不代表真实采集链路：

```text
用户原始需求 + 后续补充/确认
              ↓
本次模型输入 → 模型回复或工具指示
                         ↓
              工具/函数 + 参数 → 工具返回
                                       ↓
              后续模型输入 ← 已核对的反馈内容
                    ↓
              后续回复、再次调用或交付
```

没有采到请求、响应或反馈关联，就在相应位置显示缺口。SessionLens 的日志记录可以展示动作及返回；不能据此补写完整 HTTP 交互。

只有来源明确支持时才把一段输出标为“模型响应”；否则展示为“Agent 记录的回复”或对应源事件名称。

“已记录思路”放在对应输出或动作旁，给一句可核对的摘要，原文默认折叠。没有可读正文时显示未记录可读思路；不由工具行为补造思路。

## 6. 安全调查的查询与展示

### 搜索入口

一个输入框接收关键词、字段条件和自然语言。筛选维度包括人员/账号、设备、Agent、采集器、时间、资料类型、行为类型、工具/函数、内容位置、目的地、风险类别及处理状态等。未采到或未建立映射的维度不能显示为已有能力。

关键词搜索原文及结构字段。自然语言先解释调查意图，再形成可见的查询条件、证据阶段和范围。比如“这台设备有没有把密码发给模型”，需要同时查看敏感内容、请求正文、目的地和关联证据，而不能只在所有文本中搜索“密码”。

IP 或域名可以直接检索，但搜索结果分清它出现在正文、命令参数、目的地字段还是实际网络观测里。“提及这个地址”与“执行了访问命令”与“捕获了请求”分别表达。

查询不能只搜索最近展示的 200 条记录，也不能把索引中的截取内容当成完整原文覆盖范围。页面应分别说明平台已接收范围、索引覆盖范围和本次关联/分析范围。

### 调查结果区

自然语言问题先给直接回答：观察到了什么、涉及范围、最重要的证据和缺口。关键词查询先给匹配结果及命中位置。结果可按安全线索、账号/人员、设备、资料、目的地或关联任务聚合，不强制所有查询都变成任务列表。

每个结果优先显示：

> **行为或安全线索名称**\
> 已确认人员/账号 · 设备 · Agent · 发生时间\
> **涉及内容与去向：**资料、工具/函数、目的地等与本次问题有关的字段。\
> **关键证据：**具体命中片段、所在阶段、采集来源。\
> **范围与进展：**独立请求/任务/设备范围，已核对或待确认，处置状态。

关联任务及原始需求作为调查背景显示。一条源记录可以支持不同查询，但不能被重复计为多个独立行为。相同敏感内容在多个请求中持续出现时，保留请求级出现次数及聚合事件范围。

“发现线索”“已确认风险”“处理状态”分别表达。普通工具调用不自动标为危险，异常或违规判断要说明相对什么需求、基线或公司政策成立。

未归属记录单独保留，不为凑任务卡而强行合并。未确认员工身份不影响以账号、设备继续调查。不能拿最多三个检索候选推算全部员工、项目或外发事件数量。

### 调查详情

第一屏优先显示“发生了什么、涉及谁和什么资产、哪些资料去了哪里、范围多大、证据是否足够”。下方将命中内容放回完整过程：

```text
需求与讨论 → 材料进入输入 → 模型指示 → 工具执行与返回 → 后续输入/请求 → 结果
                    ↑ 安全线索在实际出现的节点高亮 ↑
```

链路使用实际已采关系；没有对应请求或反馈证据的位置显示缺口。每个节点只先显示动作、关键对象和结果，点开再看参数、返回、输入块和原文。HTTP 与已记录思路放在相应节点的证据入口。

需求背景用于区分用户明确提供的信息、Agent 自动装配的背景和工具产生的数据。不能把模型请求里出现的所有内容都说成员工本次主动上传。

用户沟通轮数、模型请求次数和工具调用次数分开显示。没有足够记录时给出已观察范围或“无法确认”，不互相推算。

任务关联、交付状态和证据完整性分开表达。任务关联成立不等于任务成功；Agent 说完成、工具返回一个路径，也不等于产物已经核验。

### 调查到处置

在数据中心选择相关证据，可以继续关联调查、保存调查条件和证据快照，或形成安全事件并进入交互安全审计的处置流程。处置记录包括责任人、处理动作、完成时间、后续复测证据。新证据到达后，旧结论保留并提示需更新，不能只把状态改成“已解决”。

员工行为分析先呈现观察事实、任务背景和证据。主观意图、恶意、违规和实际损失需要额外依据，不从使用次数、调用了某个工具或用了某个外部服务直接推断。

### 原文与摘要

数据中心对已接收原文按用户要求展示，不新增脱敏。摘要用于减少阅读量，已保存内容仍可从命中位置和节点进入；格式化 JSON、参数表和结果表不丢弃原始字段。源记录未上传、截断或不可读的范围另行标注，不能称作完整采集。

页面查看原文与发送片段到模型分析属于不同操作。自然语言分析沿用既有中转配置及已授权的数据范围，不因公开展示自动扩大外发范围。

## 7. 用现有采集能力落地的边界

本次只读核对的代码包括 SessionLens/sessionlens/core.py、SessionLens/sessionlens/message_graph.py、collection_knowledge.py、collection_semantics.py、collection_links.py 和 collection_view.py。

| 能力 | 当前代码支持情况 | 设计要求 |
| --- | --- | --- |
| 员工身份与行为归属 | 当前主要是上传/设备归属账号及设备信息 | 实际人员需映射证据，先区分账号、设备与操作人员 |
| 用户消息、Agent 回复、工具、参数与返回 | 有对应事件类型及原始 payload | 用适配器保留类型差异，格式化展示 |
| 调用与返回配对 | callId 存在且唯一时可建立记录关系 | 缺失/重复保留缺口，不只配最近一条 |
| 多轮任务关联 | 已有语义关联、引用校验和任务分组 | 当前主要随问题有限候选生成；需建立持续、可修订的任务目录 |
| 输入上下文 | AppLens 有 WorkBuddy 装配上下文和捕获请求正文 | 区分本地装配内容与已捕获网络正文 |
| 请求和模型响应配对 | 目前没有跨采集器统一保证 | 不能把时间相邻的回复当成精确对应响应 |
| 结果进入后续输入 | 可用已采输入块核对；不是所有记录都有对应请求 | 保留出现位置、匹配依据和歧义 |
| 交付及验证 | 可以展示回复、工具返回、文件变更等记录 | 声明、生成结果、独立验证分开 |
| 全历史搜索与目录 | 当前有增量 FTS 索引，但字段有截取；旧页面仍按有限窗口展示 | 补全结构索引及覆盖说明，不能宣称全内容已索引 |
| 进程、文件、内存、真实网络观测 | 不属于当前 SessionLens 会话日志的完整证据 | 预留 AgentReins 观测对象及关系，不由日志补造 |

原始证据、提取的结构、任务关联和分析结论分别保存。所有派生对象和关系能返回原始记录及位置，保留来源版本、解析版本和关联依据。新增记录后旧分析保留，并明确待更新。

## 8. 原型和后续开发的验收条件

1. 同一源 Session 中天气与视频任务不混淆；命中的历史背景不会自动变成当前需求。安全查询结果先表达行为和证据，任务作为背景。
2. “需求 → 讨论 → 确认 → 执行”的用户原话可见，动作对应当时有效要求；插入另一目标和恢复旧目标不混淆。
3. 搜索工具、函数、命令、参数或返回，能说明命中位置，并回到对应任务；未归属记录也能看到。
4. 工具调用与返回成对；缺失结果、重复 callId 和截断分别可见。
5. 页面能展示多次模型沟通及工具反馈循环，不能用第一轮/第二轮的装饰步骤代替真实记录。
6. 输入上下文可以定位到具体块；材料来自历史、当前输入还是工具返回有依据。
7. 地址仅出现在文本中时，不显示为实际外联；命令中包含 URL 也不自动判定网络访问成功。
8. 没有精确请求证据时不报精确模型交互总数，没有验证时不标记交付已核验。
9. 过程概览无需读完整 JSON；展开后能读到具体参数、返回和原文。
10. 首页统计、关键词检索、自然语言回答和任务详情使用同一套数据对象、关系及覆盖范围。
11. “谁做的”仅显示有身份依据的人员；上传账号和设备名称不能冒充已确认操作员工。
12. 敏感内容出现在本地背景、模型请求、工具参数等不同阶段时，结论分别表达；不把出现一次直接写成泄露或损失。
13. 员工主动提供与 Agent 自动携带分开；缺少来源证据时明确待确认。
14. 调查范围按独立请求、任务、设备等相应单位计算，不把日志副本或重传数量变成事件数量。
15. 普通行为、待核对线索、已确认风险及处置进展分别展示，能从风险回到原始证据。
