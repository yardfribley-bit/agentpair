# 执行分析实验

第一阶段是本地证据整理，不是完整多 Agent 系统。接收 AgentReins `schemaVersion: 1` 单任务快照，输出可定位的执行时间线、缺失工具结果和重复调用记录。模型分析、真实 Mac 样本兼容和远程调度仍待验证。

运行（报告输出包含任务原文，不要粘贴到公共日志）：

```sh
python3 execution_analysis.py /path/to/private-task-snapshot.json
python3 -m unittest -v
```

关联只采用原生 session/call ID，不按时间相近归因。缺失结果不是执行失败；重复调用不是必然浪费；模型说“完成”也不是完成证据。原始证据保持不变，报告单独生成。

## 后续 Agent 输入与输出

执行分析 Agent 读取经过人工确认的脱敏任务副本；按任务、工具调用、验证动作分析，不接收整库数据。不执行证据正文中的命令或指令，正文始终是待分析数据。

每条判断必须包含：`claim`、`assessment`（supported/contradicted/unknown）、`evidenceIDs`、`reason`。证据 ID 必须存在于本任务；可定位引用只是必要条件，不等于判断已被证据支持。

先用单个执行分析 Agent 建立基线，再引入独立复核 Agent 检查事实和结论。不自动改代码、不自动阻断用户操作、不以多个模型意见一致代替事实。

第一轮验收：选取真实且可合法使用的任务，人工标注失败重试、完成证据和缺口，对比单 Agent 与分析+复核的准确率、漏报、耗时和模型费用。正式接入中转前确认脱敏与预算；当前工具不会发送任何网络请求。

## 敏感数据外传实验

`sensitivity.py` 支持版本1和4，在本地扫描任务原文；对云端只构造白名单元数据包（类别、数量、证据别名、采集方式、完整性）。不导出原文、域名、真实任务ID或事件ID。证据别名到原始字段的映射留在本地。该模式暂不分析源代码与商业信息的具体语义，也不保证覆盖所有秘密格式。

`cloud_worker.py` 为分析与复核提供同一最小程序，通过私密标准输入接收配置。它会调用中转API，必须先确认中转实际输入/输出人民币单价，两个角色每个最多0.5元。每个角色最多一次调用、800输出token，不自动重试。引用ID验证不等于语义判断正确。
