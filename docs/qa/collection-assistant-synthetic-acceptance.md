# 采集知识问答的合成验收

`ops/evaluate_collection_assistant.py` 使用独立临时数据库建立 4 个 WorkBuddy 场景，共 38 条会话记录及 1 条 AppLens 上下文。提问、网址、代码、文件名和时间都是合成资料，不读取生产会话。每个场景使用独立设备，上传顺序刻意交错，以核对源记录顺序。

用例覆盖：

1. 用“气象、气温”等自然语言问法查找上海天气，核对实际请求网址与返回。
2. 会员登录方案经过讨论、非固定确认措辞、插入天气查询、恢复原需求、授权执行；天气不能混入登录任务。
3. SSH 动画需求经过修改、工具发现、生成调用及返回；参数、两个工具往返和最终文件都应保留。
4. AppLens 当前上海天气请求含旧 SSH 历史，必须归属当前天气输入，不得归到旧视频任务。

先离线检查资料构建，不发起模型请求：

```sh
python3 ops/evaluate_collection_assistant.py --prepare-only --directory /tmp/collection-assistant-prepare
```

明确运行真实中转模型验收：

```sh
python3 ops/evaluate_collection_assistant.py --private /etc/agentpair/private.json --directory /var/lib/agentpair/qa/collection-assistant-real-001
```

目录必须为空，且位于 `/tmp` 或 `/var/lib/agentpair/qa` 下。脚本只在内存读取 `relayToken`，不会复制私有配置，也不会创建云机器。`--prepare-only` 网络调用为零；正式运行会产生真实中转费用。

正确标签保存在 `ground-truth.json`，不进入模型输入。逐题结果写入 `results.json`，控制台只显示用例、阶段和通过数量。每题检查真实需求根、主题词、需求轮数、工具与对应返回归属、任务混合率、原记录存在、回答引用、关联支持状态和当前上下文归属。全部检查通过才算本题通过。

这份合成验收验证调用链和已知边界，不代表真实历史的召回率，也不能靠引用编号存在证明每一句模型回答都正确。真实历史仍需另外建立人工标注题集和语义复核。
