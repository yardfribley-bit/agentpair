# AgentPair Windows 端到端验收计划

目标：通过真实 Windows WorkBuddy 任务，验证安装、运行、采集、持久化、上报、平台搜索与展示，而非只验证安装回执或示例数据。

## 测试前阻断项

- 平台 SessionLens 安装方案 build-4c1375a 过旧，未包含最新凭据恢复、实时发现和按源轮转调度。须构建、验证并登记新包及 SHA256。
- WorkBuddy Windows 首次登录需验证可行，不能复制本机账户目录或把 CLI 会话当桌面会话。
- 平台自然语言理解/跨任务语义聚合尚未完整上线，应单独标记未完成；关键词搜索通过不等于语义问答通过。
- 机器收费需有明确上限和时限；创建前查询报价，记录幂等请求 ID，确认回收服务运行。测试失败也要释放/核对资源。

## 环境准备

Windows Server 2022，2C/4G，独立测试目录，官方 WorkBuddy 安装包、固定哈希 AppLens 包、最新固定哈希 SessionLens 包。记录真实版本、登录账号归属、两采集器使用的同设备身份。不要注入真实密码作为测试内容。

## 用例与实际证据

1. 开机：报价→用户确认→创建回执→云端运行→SSH 验证。检查任务中心阶段回应与失败恢复。
2. 安装三款软件：下载 SHA256→安装→实际二进制版本/自检→运行进程。安装成功不等于采集成功。
3. 配对：两采集器关联同一 Windows 设备；重启后保持凭据，不生成重复资产。
4. 标记问答：独特 TEST-WIN 标记，仅回复收到。两源均出现正文；SessionLens 有原始提问、回复；AppLens 采到当前输入；核对平台接收时刻而非源记录时间。
5. 文件任务：仅在临时目录创建天气示例 HTML（静态示例数据），记录工具参数与返回、产物文件及路径。
6. 多轮需求：先方案→改样式→批准执行→再改刷新按钮。任务归属与完成状态分别验收。
7. 插入任务：天气任务中插入纯文本 SSH 解释，再恢复天气任务。不能因共享 sessionId 或历史提及错误合并。
8. 搜索：原词、不同措辞、无命中、中文/英文、AppLens/SessionLens 过滤；结果必须指向真实证据。
9. 实时与历史同时工作：历史有积压时发新问题，测发现/入库/上报延迟；两个源不能互相饿死。
10. 网络故障恢复：只控制测试采集器上报连接，检查退避、持久化及恢复幂等；不改变生产网络或绕过证书校验。
11. UI：TinyFish 查看设备、采集数据、任务中心、审计、洞察；检查加载、点击、筛选、问题保持、返回导航与错误表达。Windows 本机 GUI 单独标明实测/未实测。
12. 权限：管理员、普通已登录用户、访客的既定读取范围与写操作边界。访客读取已明确公开的数据不算缺陷。
13. 性能：进程 CPU/内存、数据库增量、扫描频率、队列、最久待上传、失败重试；不要只记条数。
14. 回收：释放测试机并核对云端、磁盘、公网 IP 与平台状态，明确任何残留。

每条用例记录：输入、预期、实际、证据 ID、延迟、结论（通过/失败/阻断/未测试）。不得将模拟单元测试、浏览器机器人文字推断或源日志声明替代真实运行证据。
