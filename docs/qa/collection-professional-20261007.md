# 采集数据问答与任务关联：功能验收记录

日期：2026-10-07。环境：生产 HTTPS `www.chuhaijian.com`、既有 AgentPair 服务；真实问答使用已配置的 `deepseek-v4-flash` 中转。用户明确授权本次天气、SSH 视频和开发任务片段实测。本轮没有创建或购买云机器。

## 本轮结论

修复后，六个真实历史任务场景通过最终检查。它们验证了需求检索、任务边界、指代追问、工具证据和未知任务处理；不能将六个样本的结果当作全量历史准确率。

结构检查之外逐条人工核对回答：曾发现模型把天气接口的正常 JSON 夸大为 HTTP 200。首页的 200 有明确返回，接口状态码没有记录。补充逐网址证据核对要求后，重新运行项目回顾与 curl 追问，两项均通过，回答不再替接口补写状态码。

## 真实任务用例

独立标注来自已上传的 WorkBuddy 原始记录，正确任务根不放入模型输入。上海网页开发和溧阳天气查询在同一会话中，仍必须识别为不同任务。

| 提问场景 | 必须回答或保留什么 | 最终结果 |
| --- | --- | --- |
| 上海天气 Web 项目怎么完成 | 新建目录、写源码、启动服务、curl 测试、交付；保留中间测试的调用及返回 | 通过 |
| 追问“它 curl 到哪些网址，返回怎么样” | 沿用上一任务；列出 `http://localhost:3000/` 与 `http://localhost:3000/api/weather`，分别描述返回 | 通过；状态码夸大修复后再次通过 |
| 明确改问溧阳天气 | 切换到溧阳需求，回答 WebSearch 的查询词与搜索返回，不能延用上海网页 | 通过 |
| 五秒 SSH 动画怎么生成和交付 | ToolSearch → DeferExecuteTool/VideoGen → completed 文件 → present_files，说明关键参数 | 通过 |
| 上海开发和溧阳查询是否同一任务 | 两个独立目标，分别描述 Bash/Write 和 WebSearch；同会话不等于同任务 | 通过 |
| 不存在的唯一任务编号 | 证据不足，不拿旧任务答案补位；不返回已确认任务及引用 | 通过 |

每题检查完成状态、完整的预期任务根集合、没有额外目标、WorkBuddy 来源、证据记录确实存在及引用有效。工具类问题额外检查具体 URL/工具名和中间测试记录是否保留。引用有效仅证明引用存在，回答内容仍需语义核对。

最终六题用时约 4.1–22.2 秒；状态码修复后的两题复测用时约 18.4–20.4 秒。这是本次样本观测，不是性能承诺。机器可读结果见 [collection-professional-20261007.json](collection-professional-20261007.json)，只保留验收指标，不发布原始会话正文或凭据。

## 本轮发现和修复

| 问题 | 实际影响 | 修复及验证 |
| --- | --- | --- |
| 扩展搜索词占满候选 | 短的原始需求被长工具正文挤出，SSH 原目标曾落到第 70 名 | 多查询通道、用户需求候选保留、来源/会话轮转；噪声回归与真实 SSH 通过 |
| 追问丢失任务身份，改问又沿用旧目标 | curl 追问或切换城市会串任务 | 服务端保存上一任务身份；保留新问题全局候选，复核新目标；上海→curl→溧阳实测通过 |
| 关联摘要被当成完整回答证据 | 长轮次中间的测试与工具返回缺失 | 关联后恢复选中轮次的真实动作，再控制回答证据预算；中间 curl 调用/返回保留 |
| 选中任务后重建图，只剩一个重复 callId | 原本不明确的工具返回被错误升级成确定配对 | 在完整保留窗口按源文件顺序核对关系，再筛选任务；歧义仍待确认；搜索返回锚点也禁止任选第一条调用；重叠窗口的局部序号不能改变调用先后 |
| 模型关联 JSON 不合法 | 任务问答直接失败 | 一次有限的模型结构修复；仍不合法就失败，不本地编造关联 |
| 正常 JSON 被解释为 HTTP 200 | 测试结果被夸大 | 回答与复核阶段逐个网址核对；真实 curl 追问再次通过 |
| 旧证据不在最近摘要中 | 点击原文找不到内容或一直读取 | 支持直接读取指定记录；原文失败明确结束读取状态；生产历史正文读取通过 |
| 自动刷新使用旧选择 | 用户刚切换记录又跳回上一条 | 摘要返回时读取当前选择；阻塞响应、期间切换记录的回归通过 |
| 刷新丢失问答 job；重复提交；丢失 job 无限重试 | 重复调用模型、看不到结果或无法恢复 | 保存待完成 job，刷新只 GET；后台同请求去重；404 后明确重新提交 |
| 切换设备/采集器保留旧搜索结果 | 用户在错误范围里查看旧结果 | 清理旧状态，异步返回核对范围与代次 |
| 非字符串 previousQuestionId 导致断连接 | 前端得不到可处理的错误 | 参数验证，生产返回 JSON 400，未创建问答 job |
| 撤销设备后仍开始下一次模型调用 | 权限失效后继续处理数据 | 每次模型阶段前后重新核对设备权限，禁止后续调用与完成结果 |
| 钱包先扣，再发现全局预算不足 | 没有启动模型仍扣费 | 钱包与全局预留在同一 SQLite 事务中校验和提交；拒绝时双方回滚 |
| 首屏展开几十条过程与引用 | 日常问答阅读量过大 | 任务详情默认折叠；先显示六个引用，需要时展开全部 |

## 回归与线上检查

- Python 全套回归：197 项，其中 184 项通过，13 项因本机没有 Windows/PowerShell 环境而跳过；跳过项不能算通过。
- 页面交互：14/14，通过实际页面 JS 与合成 DOM/API 执行；另有设备全局视图、任务回复反馈回归通过。它们验证交互状态，不等于真实浏览器视觉验收。
- 云机器工作流/HTTP 的已有回归使用合成云 API，没有购买资源。
- 生产 HTTPS 首页、设备、采集数据、安全审计、会话洞察、云机器、软件包及页面 JS 均返回 200；游客设备列表有数据，历史指定记录可读。
- 游客调用问答读取返回 JSON 401；登录后的非法关联参数返回 JSON 400，未创建模型 job；验收结束没有遗留运行中的问答。
- 部署保留逐次备份、生产文件哈希检查和失败回滚；最终核对线上五个源文件与本机一致。

```python
import unittest

modules = ['tests.' + p.stem for p in sorted(Path('tests').glob('test_*.py'))]
result = unittest.TextTestRunner().run(
    unittest.defaultTestLoader.loadTestsFromNames(modules)
)
assert result.wasSuccessful()
```
