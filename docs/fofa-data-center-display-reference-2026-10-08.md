2026-10-08，北京时间。用户最终要求不登录访问；此前的登录自动化已取消。TinyFish 以 fresh session、use_profile=false、use_vault=false 访问官方 FOFA，完成12步、约141秒的有范围检查。

## 实际观察范围

查询一台已授权服务器的公网地址，查看结果页、数据统计、公开展开控件。没有扫描服务器、导出、购买、修改账号或解决验证码。

TinyFish记录：原始运行记录保留本机。

- 顶部保留查询表达式；检索结果、数据统计、历史趋势分开。
- 同时设置“匹配结果”和“独立IP”计数，游客显示为 `*`；不把侧栏可见的6项数据宣称为完整资产总量。
- 左侧聚合面板可看到国家/地区、端口、协议等分布，统计项有筛选交互。
- 主结果围绕资产对象排列，包含域名/标题、IP、端口、地区、ASN/组织、时间及识别信息。
- Header、Banner、Products、证书等证据分块或折叠，避免把原文全部放在首屏。
- 有列表/网格切换及分页位置；完整分页、更多数据、历史趋势等游客功能受限。

这不是 FOFA 内部 Skill/MCP 调用链的观察，也不能把一次 FOFA 搜索当作它实时调用了多种工具。报告中的 UI 字段由 TinyFish 浏览器观察返回，未另行验证 ASN、版本、地理位置等信息的事实准确性。

## 对 AgentPair 的设计对应（推断/建议，未据此开发）

| FOFA 展示层 | AgentPair 数据中心对应 |
| --- | --- |
| 查询表达式 | Skill/MCP/工具/命令/地址/文件等组合条件，命中字段可核对 |
| 匹配结果数 + 独立IP数 | 匹配原始记录数 + 需求组数 + 涉及设备数，明确各自粒度 |
| 结果内分布与筛选 | 当前命中范围内的设备、Agent、上传账号、Skill、MCP、工具分布；点击添加或排除条件 |
| 资产对象及短字段 | 需求标题、机器、Agent、时间范围、命中能力及关键参数/返回，原始调用放在组内 |
| Header/Banner等证据块 | 用户原话、调用参数、返回、已记录思路和上下文分区；原文默认折叠 |
| 数据统计、历史趋势 | 命中范围统计与时间分布，独立于逐条原文详情 |

FOFA 的资产与端口粒度不同于我们的需求与调用粒度。沿用“按需求 / 按原始记录”两个视图，不因同一Skill名称就合并多个真实需求。候选归属仍保留标记。

本轮没有更改 AgentPair 权限、访客访问、登录条件或收费流程；FOFA 的游客门槛不是我们的功能要求。

## 用户明确的三层展示合同

2026-10-08 用户进一步明确以下结构。此节是后续展示设计合同，不代表完整详情页或 Skill 产物关联已经实现。

1. 所有查询固定展示 Agent、上报机器、用户原始需求和发生时间。关联不明确时保留记录并标明候选或未关联，不能用“做”等确认短句替代已确认的完整需求。
2. 中间的重点由查询对象决定。`tool="exec"` 展示实际执行代码/命令、参数、返回；`skill="taste-skill"` 展示如何加载或读取、返回的指南、使用后可核对的执行及任务产物；MCP 展示服务、方法、参数和返回。不能把所有搜索都渲染成同一组泛化正文。
3. 点击后查看完整调查详情：固定用户需求与机器；按轮次组织 SessionLens 提问、回复、工具调用和返回；展示相关 AppLens 模型请求上下文并定位匹配片段。来源、调用配对、关联依据与未采集部分可核对。当前相邻记录详情不等于完整多轮任务，后续须按任务关系加载，而不是只取固定数量的时间邻居。

## Skill 查询的重点内容

| 内容 | 用户要看懂的事 | 可核对证据 |
| --- | --- | --- |
| 使用目的 | 用户要求完成什么，为什么这里使用 Skill | 原始需求、用户指定 Skill 的消息；选择理由只引用已记录内容 |
| 调用方式 | 什么时间通过哪个工具加载，传入了什么 | 工具名称、调用 ID、读取命令/参数、说明文件路径 |
| 直接返回 | Skill 加载或说明读取实际返回了什么 | 同作用域唯一调用配对的返回、已采集指南摘要、原文入口；外层返回单独标注 |
| 后续执行 | 后面做了哪些动作，参数与结果是什么 | 原生父消息/轮次/任务关系；仅时间相邻标为候选，不推断因果 |
| 任务结果 | 生成的页面、代码修改、文件在哪里，是否成功 | 同任务已采集执行返回、修改记录、产物路径/地址；存在成品预览时提供预览入口 |

读取 `SKILL.md` 返回的是指南，不是页面、代码或其他最终产物。页面可以把“说明返回”和“任务产物”同时展示，但不能将同一轮中任何后续动作归功于该 Skill。未取得产物或未建立任务关联时，应显示“后续结果尚未关联”，并保留已采集内容供继续调查。

### 待补齐能力

- 列表当前已支持加载工具、参数及说明/外层返回；还没有通用 `Skill → 任务产物` 合同。
- 完整调查页的多轮任务聚合、SessionLens 与 AppLens 对齐、产物预览仍需单独实现和验收。
- 原生父消息与轮次编号指向不同输入属于证据冲突，应降为未确认，并排除跨需求后续动作。

## exec 返回的可读性合同

用户提供的示例包含 `Script completed`、`Wall time`、`Output`，里面再嵌套 `{i, chunk_id, exit_code, output}`。这些是执行器包装，不能作为面向用户的结果摘要。2026-10-08 已实现普通 exec 的有界静态操作拆解、包装返回解码，以及列表/分组/详情中的可读展示。动态代码不能全面静态还原；完整多轮任务画像和 Skill 最终产物关联仍待后续实现。验收依据见 `qa/data-center-exec-readable-2026-10-08.md`。

- 首先结合 exec 输入代码与实际返回拆出内部操作。每个操作显示“动作 → 对象 → 结果”：例如在确有 `sed` 读取命令时显示“读取代码 → 具体文件与行段 → 读取到的内容/错误”；不能只看到返回正文含 `db.execute(...)` 就认定执行了 SQL。
- 相互独立的内部操作分成节点，按实际关联标识配对。`i` 只在输入和输出确有相应下标映射证据时用于对齐；不能把任何 `i=0` 都归为第一条静态工具调用。无法拆分子返回时，明确显示外层返回并保留完整展开入口。
- 一个操作默认显示一条客观摘要与几个关键值，参数和正文分别展开。代码保持代码格式；JSON 用字段/数组表；命令结果以标准输出、错误、退出码区分；文件产物给路径与预览；搜索结果展示条目标题和内容。
- 外层“脚本执行完毕”不等于工具成功或业务任务完成。内部 `exit_code=0` 只证明该命令正常退出；代码修改是否生效、测试是否通过需要各自返回证据。耗时保留为元信息，`chunk_id` 等调试标识默认收起。
- “已取得工具返回”仅是采集状态，不作为结果内容。解析失败、采集截断、未配对子返回各有明确提示，不用模型编造缺失结果。
- 静态拆解不执行用户代码。限定内容大小、嵌套深度与解包次数，基于已采集信息投影；不为每条历史记录新增模型请求。

预期卡片顺序：用户需求与设备 → 内部操作概览 → 选中操作的动作/对象/结果 → 参数、返回与完整任务详情入口。首屏不铺开日志封装或大段代码。
