# 采集数据：自然语言问答与跨采集器任务关联

目标：用户提出一次需求，能从 AppLens 的输入上下文与 SessionLens 的多轮会话中找到需求、讨论、确认、执行、工具结果和交付。会话、记录、任务是不同实体。

## 已有能力与新增边界

- 平台历史关键词搜索和同会话过程概览已经上线；不是语义检索。
- 本地 SessionLens 的 semantic_lineage 已支持多轮需求归属、证据引用、输出校验和缓存。平台应复用其判断协议，而非另做“继续/做”词表。
- collection_links 先建立跨来源候选证据边。共享 request/turn/call 标识表示记录连接；只有 sessionId 表示同会话候选，两者都不直接证明同任务。

## 处理链路

1. 入库保留账号、设备及其别名、应用、来源标识、原始证据，不按机器名称合并。
2. 提取真实用户消息、回复、已记录 reasoning、工具参数与结果；历史回灌、压缩总结和 encrypted_content 不当作新的用户要求。
3. 结构关联先用 request/turn/call 标识，再用同会话候选范围。时间只帮助排序，不能独立建立任务关系。
4. 自然语言检索规划从问题提取目标、实体、项目与限制；检索返回若干候选需求，而非直接选一条关键词命中。
5. 模型结合需求、前后讨论与执行证据判定 request/discussion/revision/approval/execution/resume/unresolved；保留证据引用和歧义，不一路追父消息到会话起点。
6. 把不同来源的证据挂到需求轮次上。AppLens 重复携带旧历史不能使旧任务被错误并入当前任务。同名/同主题的新实例可以拆开。
7. 校验引用存在、无冲突归属、应用与设备边界一致；证据缺口显示给用户。结果按输入内容摘要与模型版本缓存。
8. 展示先回答问题，列任务候选与关联依据，再展开需求变化和执行链。每阶段可查看 AppLens 上下文、SessionLens 消息或工具原文。

## 验收

- 需求 → 讨论 → “做” → 工具执行归入同任务，措辞替换也成立。
- 插入另一个目标后恢复旧目标，不能把两个任务合并。
- 同一 sessionId 里的天气与视频分开；历史上下文里提到 SSH 不意味着当前正在做 SSH。
- 同一请求的 AppLens 与 SessionLens 记录能共同展示；缺少相同标识时应有可核验的语义依据。
- Codex 与 WorkBuddy、不同账号/设备不能因标识或关键词巧合错误关联。
- 模型编造引用/冲突归属要拒绝落库，不作为已确认结果。

## 当前进度

已实现平台自然语言问答、持久化索引、多轮需求关联、跨采集器候选核对和证据前端。`POST /api/collection/questions` 提交异步问题，`GET /api/collection/questions/{id}` 查询进度和结果；提问保留在输入框中，先显示回答，用户随后展开讨论、执行、上下文和原文。追问带 `previousQuestionId`，只承接同一提问者、数据账号和设备的已完成问题。

`collection_knowledge.py` 在独立 SQLite WAL/FTS 数据库做增量投影，保留源记录，优先新上传再补历史。当前平台用模型扩展检索表达、比较候选和判断多轮语义归属，**未在平台启用向量 embedding**；候选召回仍受本地 FTS 与索引覆盖范围限制。本机 SessionLens 的向量功能与本次平台实现分开验收。

`collection_semantics.py` 复用 SessionLens 的消息图与语义关联协议。工具返回优先通过 callId 回到调用；源 turnId、父消息只用于轮次和记录关系。每次最多关联 24 个用户轮次、返回 3 个候选任务。记录按源文件偏移/轮转顺序或可靠时间排序，上传顺序只作为回退。合并多个检索窗口后重新统一顺序；中间省略用户轮次会提示缺口。

AppLens 仅提取请求中最后的真实用户输入候选，再与同应用、同设备、同会话的需求核对。历史复述不当作新任务，相同“执行吧”在不同任务重复时保留歧义，包括重复发生在当前窗口外的情况。缺少共用请求标识时，展示为“语义关联”，不宣称捕获了同一次网络请求。

回答最多提供 60 条关键证据，优先需求、当前上下文、最终回复和命中位置，工具调用与返回成对、跨候选均衡选取。省略数量显式提示；回答与复核只得到实际选入的阶段。不能从最多三个检索候选推算全部项目数量，也不能以工具次数代替模型交互次数。

模型使用既有中转的 `deepseek-v4-flash`，每次先遮盖可识别凭据，仅发送候选片段，不批量发送全部历史。未经校验的引用、未来需求和越过账号/设备/会话的归属不入缓存。缓存命中不重复调用模型；新调用接入现有平台预估额度账本，普通用户使用提问者额度。平台最多同时处理两个问答。
