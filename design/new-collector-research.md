# 编程 Agent 采集与执行过程展示研究

日期：2026年10月3日。范围：参考本机 AgentReins Windows 源码、已采集的 WorkBuddy 天气任务及官方资料，提出独立新采集器设计。本文是研究建议，不是已经实现的能力，也没有修改 AgentReins。

## 主要结论

采集深度由证据链完整程度衡量：用户需求 → 每次实际模型请求 → 模型返回的工具调用 → 工具执行与系统活动 → 返回内容 → 后续请求实际包含的材料 → 文件变化和验证结果 → 最终交付。采集广度由能观察到的行为和数据源衡量，不能把“支持某种工具”当作“执行过该工具”。

应采用两条互相校验的采集通路。应用侧负责完整消息、调用参数、工具返回、请求组装与生命周期；系统侧负责进程实例、文件和连接行为。二者通过真实调用与操作标识关联。无法关联时保留两个事实和证据断点。

## 源码核对结果

本次只进行了源码检查，没有在 Windows 实机运行采集。以下“存在”只指代码存在和可读的逻辑路径，不表示所有现场数据都能取得。

| 领域 | 本机代码中存在的实现 | 当前限制或需要核对的地方 |
| --- | --- | --- |
| 用户任务与背景 | WorkBuddy adapter 从私有 JSONL 提取 user_query 和上下文章节 | 私有格式需要逐版本适配；user 消息正文并不是每轮完整 HTTP 请求 |
| 工具参数和结果 | function_call、function_call_result 保留参数、输出和 callId | 缺字段、未知类型应显式报错；同源调用标识才能正确配对 |
| 模型回答 | assistant 消息生成响应事件，识别最终消息 | 这是应用记录；不能默认与原始网络响应完全等价 |
| 进程 | ETW 启停、父进程与进程实例，命令行存在可选采集路径 | 不是每条记录都带命令行；PID 复用需要实例身份排除 |
| 文件 | 开启、读写、删除、重命名及操作结果；使用 FileObject、IrpPtr、TTID、IoSize | 没有在这条路径取得文件实际读写正文；IoSize 是请求字节数，不应一律宣称实际完成字节数 |
| 网络 | 连接、发送、接收、断开及地址端口、连接标识、字节记录 | 未在该 ETW 路径看到 HTTP 业务正文或 TLS 解密内容；搜索返回的网址不证明本机访问了它们 |
| 内存与资源 | working_set_bytes、private_memory_bytes、CPU 和进程权限采样 | 这是资源统计，不是进程内存中的对象、字符串或缓冲区内容 |
| 因果关联 | 原生标识匹配、confirmed/partial/unlinked、first_breakpoint | 同进程活动不能直接归因到同一个工具；缺操作关联标识时仍然有断点 |

## 做深：记录数据的变化和去向

### 每轮模型往返

独立保存实际请求与响应，标记来源为网络、SDK、应用 trace 或会话记录。保存消息序号、角色、工具定义、模型字段、请求 ID、调用 ID、时间、结束原因与完整性。流式响应保留分片和重建规则，失败、取消、重试、自动标题等辅助请求独立记录。服务端工具执行若只能看到返回结果，不补造本机进程或连接。

相邻请求做内容对比：哪些消息原样沿用，哪些新加入，哪些被截断、摘要或移除。仅凭正文变短不能确定是模型压缩；没有摘要事件时，只说明观察到的内容差异。记录保存上限、采集截断和模型实际输入截断分别处理。

### 工具执行

把调用、启动、输出、结束、取消和重试分开。记录参数、工作目录、权限决定、stdout/stderr、退出码、返回正文以及应用交给模型的版本。有的工具输出会先被截断或加工，因此“工具原始结果”和“下一轮模型拿到的结果”不能合并成一个字段。

### 文件内容

工具层记录实际 Read 返回片段、Edit/Write 参数和结果。应用可提供 file-history 时保留版本；另做按任务范围的前后快照，以文件身份、内容哈希、版本时间和实际差异记录结果。事后读取当前文件只能叫当前快照，不能宣称它就是先前实际读到的字节。

把文件读入片段映射到后续消息：原生引用或应用组装标识支持确认关系；仅相同文字支持内容匹配，不直接证明来源；转换、摘要或相同内容多处出现时保留候选来源。对代码修改展示 diff、写入结果、后续测试和最终文件状态。

### 网络内容

系统侧保留连接归属与传输事实；应用侧记录 HTTP/SDK 的请求响应。在可观测边界取得明文时才展示正文。连接复用、HTTP/2 多路复用需要请求/流标识，不能按一个 TCP 连接等同一次模型调用。显示解码正文与传输字节的不同口径。

### 内存

分别呈现三类东西：进程资源用量、应用内部可观测对象/缓冲区、Agent 持久记忆资料。优先用应用日志、扩展或运行时插桩记录明确对象的版本变化，例如上下文缓冲区、工具结果对象和待发送请求。对不可插桩的进程，原始内存采样需要另外验证权限、地址、布局和采样一致性；读到字节不等于能解释用途，不承诺读取全部内存并恢复所有语义。

## 做广：增加行为覆盖，保持同一任务归属

逐步覆盖：Shell/PowerShell、文件读写与目录搜索、模型接口、MCP、本地浏览器、依赖下载与安装、Git 工作树变化、测试/构建、持久记忆、技能/项目规范、权限审批、子 Agent、计划与调度。每项都回答“是否可用、是否调用、是否执行、返回了什么、进入了哪个后续请求”。

增加 Agent 时采用独立适配器和明确版本支持范围，统一事实字段，不假设 WorkBuddy 的私有 ID 是通用 Trace ID。系统层按 Windows/macOS 的可用接口分别实现，统一展示语义，而不是强行使用相同底层技术。

## 关联与证据结构

最小实体：任务、用户消息、模型请求/响应、工具调用、工具执行、进程实例、文件版本/片段、网络请求/响应、应用缓冲区版本、验证结果与交付产物。

每个实体保存：稳定 ID、来源作用域、原生标识、源时间与观察时间、正文引用及哈希、状态、完整性、限制。

关系独立区分：包含/归属、调用与结果、实际执行、数据进入请求、内容对应。确认、部分关联、仅内容匹配和未关联分别呈现。时间邻近用于寻找候选，不用于确认因果。PID、名称或路径相同不能替代实例与版本身份。

## 展示：系统活动必须接在执行动作上

保留已认可的模型往返动态主线。网络、进程、文件和内存是执行动作周围展开的真实对象，不是旁边四块静态说明。

例如修复代码时：模型提出 Bash → 命令进入终端 → 子进程实例出现 → 测试读取文件 → stderr 报错返回 → 报错进入模型下一轮请求 → 模型提出 Edit → 文件前后差异出现 → 再次测试 → 最终回答。此例只是目标展示场景，不是本次天气任务发生的动作。

材料名称与关键片段沿留白通道交接，正文在稳定位置保留。当前动作突出，完成路径保留。高频 OS 事件按已确认的执行单元和资源分组，用户可展开完整证据；聚合不丢弃原始记录，不把无关联行为画成已确认动作。历史回放明确标注，与实时到达动画分开。

展示检验：用户不用打开原 Agent，能否说清任务、每轮模型返回、工具实际动作、系统影响、材料去向、验证结果和未完成部分。每个陈述都能找到原文证据；没有证据的关联明确断开。

## 推进顺序

1. 在独立测试目录中建立固定样本，不操作其他项目。天气任务核对往返；编程样本预置一个小函数、失败测试和可重复输入。
2. 先贯通任务、完整请求响应、工具参数/输出、文件 diff 与测试结果，再接进程/文件/网络系统活动。
3. 对身份、并行调用、重试、断线、晚到结果和截断进行核对。
4. 针对具体应用缓冲区尝试内存对象采集；原始进程内存研究单列，不阻塞主链。
5. 原型先讨论：每次只增加一种真实系统活动，检验内容仍然可读、动画仍然清晰。
