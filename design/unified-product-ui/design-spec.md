# AppLens、SessionLens、AgentPair 统一界面设计

版本：2026-10-07 · 终端产品形态修订 · 可交互原型阶段。

设计判断：面向普通 Agent 使用者与安全管理人员的工作台。清晰、克制、可追溯；先理解结果，再查看过程和证据。

## 设计范围

**AppLens、SessionLens 是安装在 Mac / Windows 上的独立桌面应用。AgentPair 是 Web 平台。**

统一配色、字体、按钮、状态语义和证据内容规范；分别设计桌面窗口与网站外壳。客户端原型使用 HTML 表达界面，不改变其交付为桌面应用的产品形态。AppLens macOS 现有本地 WebView 仍由原生应用承载，SessionLens 保留 Qt 桌面技术栈。

| 产品 | 首屏回答的核心问题 | 主入口 |
| --- | --- | --- |
| AppLens | 这次向模型提供了哪些上下文？它们怎样被采集和上报？ | 采集总览、上传记录、连接设置 |
| SessionLens | 过去做过什么任务？为什么这样做？用了什么工具，结果有何依据？ | 智能助手、历史任务、采集与同步 |
| AgentPair | 平台现在什么情况？发现什么问题？在哪些资产上？如何推动处理？ | 任务中心、我的设备、采集数据、交互安全审计、会话洞察、云机器、软件包 |

产品切换位于原型预览条，是评审用控件。安装到用户设备后不出现产品切换或 macOS / Windows 选择器。窗口外壳预览通过原型评审控件切换，正式应用自动适配系统。Codex、WorkBuddy 是来源，两个客户端保持独立状态。

本次原型默认打开 AppLens 桌面窗口，便于直接核对终端形态。AgentPair 平台仍可在预览条中查看。

## 共享基础规范

基础值见 `tokens.json`，原型对应使用 `--ap-*` 变量。

| 项目 | 规范 |
| --- | --- |
| 背景 / 内容表面 | `#F7F8FA` / `#FFFFFF` |
| 正文 / 次要文字 / 边框 | `#172334` / `#637084` / `#E6E8EC` |
| 主强调色 | `#2463EB`；只用于主要动作、选中与运行阶段 |
| 页标题 / 区块标题 / 正文 / 元信息 | 22 / 17 / 14 / 12 px；正文行高 1.6 |
| 字体 | 系统字体；中文 PingFang SC，Windows Segoe UI；原文使用等宽字体 |
| 外壳 | AgentPair 网站侧栏 196 px；终端应用侧栏 164 px，原生标题栏与底部状态栏 |
| 圆角 | 内容表面 12 px，按钮 7 px，状态标签 5 px |
| 间距 | 主内容 28 px；区块间 22 px；可选紧凑密度 16 px |
| 图标 | 同一线性图标体系；保留已有品牌资产 |

绿色：有回执或明确完成证据。蓝色：进行中或选中。琥珀色：待核实、待重试、部分完成。红色：高风险或明确失败。灰色：未接入、未知、中性元信息。所有状态必须同时有文字，不能只靠颜色判断。

采集器的“正在采集”可使用绿色的健康状态；管道中正在处理的阶段使用蓝色。运行健康与处理进度是两个字段，不能混用。

## 原型中的页面

### AgentPair

1. **任务中心**：大输入区、简短答案、相关设备/任务对象、证据入口。查询过程默认折叠。保留新问题；无法演示的问题清除旧答案，不能显示上一个任务的结论。
2. **我的设备**：设备名称、负责人、部门、系统、地址、设备标识和多个采集器状态。设备范围、关键词搜索有效。接入设备作为页级动作。
3. **采集数据**：以同一次任务组织 SessionLens 的会话记录和 AppLens 的模型输入。可以按来源筛选、搜索、查看关联依据和原始证据。未匹配时清除旧结果。
4. **交互安全审计**：发现列表 → 证据与影响 → 负责人、处理步骤、复验依据。示例包括凭据进入模型输入，以及待核查的执行隔离问题；后者不宣称已经证实越过沙箱。
5. **会话洞察**：先给交付结论及核验范围，再展开一段任务过程；工具输入、返回和交给 Agent 的信息在同一过程内展示。
6. **云机器 / 软件包**：提供与统一外壳匹配的空状态和下一步入口。原型不执行创建、购买、安装操作。

### AppLens

1. **采集总览**：请求列表与选中请求详情分栏，点击不同请求改变内容和证据标识。当前需求、项目背景、历史对话、请求里的工具返回、未确认来源分别解释“是什么、为什么会被带入”。
2. **采集回放**：发现请求 → 读取正文 → 分类保存 → 发送平台 → 确认接收。点击阶段或播放可更新当前说明。
3. **上传记录 / 连接设置**：请求内容、保存状态、回执与目的地分开展示。
4. **桌面操作**：暂停/恢复采集、查看本机记录目录、打开选中请求正文、核对 AppLens 回执；“在平台查看”对应打开 AgentPair 网站，原型中切换到平台视图演示。

AppLens 的工具返回证据是模型输入正文里的片段，不冒充独立工具事件。平台回执证明采集记录入库，不证明模型服务接收。

### SessionLens

1. **智能助手**：输入首先可见。答案先给出工具分工或项目结论；过程按步骤展开，原始返回可以进一步核对。
2. **历史任务**：按 Agent 与关键词筛选。开发项目和不归属项目的临时任务分开保留。
3. **采集与同步**：Codex、WorkBuddy 同时展示接入状态。实时追加、历史整理、本机保存和平台确认分别表达。
4. **桌面操作**：新对话清空本次输入与结果；最近问过在本机保留。右侧证据窗格支持收起，底部展示本机任务库与采集入口。

对 WorkBuddy 的项目查询不能混入 Codex 项目。不同项目入口必须打开自身的证据。

## 证据交互与文案

AgentPair 使用网页详情抽屉。两个客户端使用桌面分栏详情窗格，保留主内容，支持收起与 Escape 关闭。窗口较窄时上下排列；正式桌面实现按原生分隔控件提供拖动宽度。内容顺序：证据类型 → 状态 → 对象标识 → 可理解摘要 → 记录内容。

工具证据至少需要：工具名、调用标识、参数、网址/路径、返回内容、明确失败或缺失的字段。长 JSON 应用结构化字段解释；完整原文按需展开。不能从“正常 JSON”补写“HTTP 200”。

推理、执行说明和工具返回必须使用不同标签。原型中的天气过程没有装载 reasoning 原文，因此标为“执行记录摘要”，没有伪造思路。开发接入时，只有来源实际提供的 reasoning 才放入该类型。

文案用具体事实描述，例如“这份模型输入里包含服务器登录信息”“数据已保存在本机，尚未取得平台回执”。避免用大段系统说明替代问题、证据与操作。

## 动态与响应式

采集和执行回放分别使用独立状态。只有用户启动播放后才推进；切换页面或产品停止回放。阶段选择只展开当前内容，不累计铺满全部轨迹。

动态只表达数据移动和阶段变化，不使用装饰性粒子、持续闪烁、霓虹光效。遵循 `prefers-reduced-motion`。

原型设置 820 / 660 / 410 px 响应式规则：侧栏缩小或转为顶部导航、内容行重排、证据面板不超出产品宽度。无 `position: fixed` 或视口高度绑定。正式桌面实现保留平台原生窗口行为。

桌面窗体与窄宽度原型预览分开处理：正式应用保留合理最小窗口尺寸，窄宽度重排用于在对话中预览，不意味着将客户端改成手机版网页。

## 终端窗口行为

- macOS 标题栏与 Windows 标题栏分别适配；内容与状态规范共享。网站头像、账号范围、平台面包屑不进入终端窗口。
- 最小化：隐藏窗口，采集状态保持不变；原型中可恢复窗口。
- 关闭：按当前代码退出并停止采集，不暗示已有后台托盘常驻能力。AppLens macOS 的 `applicationShouldTerminateAfterLastWindowClosed` 返回 YES；Windows 的 `FormClosing` 停止采集；SessionLens `closeEvent` 停止计时、运行时并关闭采集器和数据库。
- 原型提供关闭提示与重新打开入口，只改变示例，不操作真实运行中的应用。
- AppLens 和 SessionLens 的暂停状态独立保存；暂停一个不能改变另一个。
- 本机保存位置按系统适配。AppLens macOS 为 `~/Library/Application Support/AppLens/telemetry`，Windows 为 `%LOCALAPPDATA%\\AgentPair`；SessionLens 为各系统的应用数据目录下 `SessionLens`。

## 后续开发约束

确认原型后分别实施桌面应用和 Web 平台，保留业务 API 与路由。共享基础 token 与组件内容规范；网站 CSS、AppLens 桌面外壳和 SessionLens Qt 控件各自适配。

| 技术载体 | 需要接入的部分 |
| --- | --- |
| AgentPair 网页 | 共享外壳、按钮/表单/状态/列表/证据组件；清理重复覆盖 |
| AppLens macOS HTML | 合并外壳与采集区重复标题，保持消息桥、分类与回执逻辑 |
| AppLens Windows WinForms | 统一布局与间距，替换固定坐标布局，沿用采集与上传逻辑 |
| SessionLens Qt | QSS 和组件尺寸映射 token；保留现有问答、关联、原始依据和回放 |

上线验收需检查真实数据、加载/异常/空状态、键盘操作、长文本、不同窗口宽度、中文与英文。不能以“接口正常”代替“界面可用”，也不能以统一配色代替信息结构统一。
