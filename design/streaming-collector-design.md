# 新采集器：流式采集与任务证据链设计

设计日期：2026-10-03。阶段：架构设计，未实现、未性能验证。

## 目标与当前依据

沿用流式架构方向，解决采集性能、工具内部不可见、关系无法解释三个问题。采集器独立于分析与动画；用户必须同时看到过程、数据、发现和缺失。

本机 agentreins-windows 当前提交 dc39ea2（2026-09-29）。已见 ETW 有界输出队列、独立写入线程、滚动输出及丢失指标；不是用户提及的最新版本的确认。最新版本位置待提供。性能瓶颈尚未实测，不能归因于单一模块。

## 三条独立通路

1. 事实通路：来源适配器 → 有界接入队列 → 追加事件日志 → 增量索引及关联。
2. 内容通路：正文或产物 → 分块内容存储 → 内容引用；事件仅携带摘要、长度和引用，不重复复制全文。
3. 展示通路：索引提交通知 → 按任务读取增量投影 → 前端局部更新与有限动画。

安全分析异步订阅已提交事件，耗时分析不得阻塞事实持久化。正文分析也不在 OS 事件回调内执行。

## 事件与内容

统一事件字段：event_id、source_id、source_seq、source_epoch、event_time、observed_time、task_id、session_id、model_request_id、tool_call_id、process_instance_id、operation_id、event_kind、status、evidence_ref、capture_quality。

字段未知时为空，不编造。process_instance_id 含进程启动身份，不能只用 PID。文件版本不能只用路径；记录能取得的文件身份、大小、版本指纹。内容指纹做去重和完整性核验，不单独承担因果证明。

模型请求通过正文引用和消息清单保存。复用历史内容时仍保留每次请求的顺序、参数、角色和精确版本，能够重建该次完整输入；不得去重到无法证明当次发送了什么。流式模型响应保留增量序号与完成状态，聚合显示为一条响应；取消、断流不能显示为完成。

## 分层采集与性能

常驻：任务消息、模型与工具边界、工具返回、进程启动退出、执行隔离状态、连接元数据、采集健康。

按任务范围启用：Agent 派生进程及已确认的工具代理进程的文件/网络事件；本地 editor_sdk 等共享服务通过请求标识关联，不能归入该服务所有活动。捕获不到原生标识时保留“关联未确认”。

按需：具体文件版本差异、指定连接的请求响应内容、产物元数据。任何额外协议适配必须说明覆盖范围，不能承诺任意 TLS 内容都可见。

不默认采集：全机所有文件正文、进程内存转储、全磁盘扫描、高频全进程资源采样。

日志只从持久游标追加读取，支持截断/轮转检测和来源重启；不用反复读取整个日志。重型解析独立工作池，有并发上限、字节配额和超时。磁盘追加写分段、批量索引提交；设置保留与磁盘上限。视频二进制不反复搬运，默认只保存版本身份、元数据和受控预览引用。

内存预算按字节和事件数双重限制；历史内容引用支持生命周期管理。关联窗口有界，晚到证据从索引查询补联，不在内存永久保留全图。

## 背压、丢失与恢复

按重要性分队列：工具边界、错误和身份事件优先；高频读写和网络计数可聚合。同一资源连续事件可总结时间范围、次数与字节，但不得合并不同结果、权限变化或版本变化。

有界队列满时不得阻塞 OS 回调、造成被观察应用卡顿。先削减展示和资源采样，再按策略降低高频明细；关键流持久化失败、OS 丢失、正文截断均产生覆盖缺失记录。高优先级也不承诺绝不丢失。

序列按来源定义；恢复用提交游标和来源代次，去重保证幂等，不宣称跨来源全局 exactly-once。网络上传采用本地持久队列、批量压缩、确认水位及重试；离线仍可本地观察。确认代表平台入库，不代表模型服务收到数据。

## 三个场景的闭环

### 写代码
用户需求 → 模型指令 → Write/Edit → 文件版本 → Bash → 进程 → 监听/连接/文件活动 → 测试返回 → 下一次模型请求 → 交付。

这次本机进程与 Seatbelt 证据为任务后独立取证，尚非采集器自动持续能力。新设计在进程启动后异步采样隔离状态，查询失败、权限不足要明确标记；检测不改变目标进程权限。区分工具审批模式与 OS 隔离。不同平台分别实现原生隔离状态检测。

### 生成视频
用户需求 → VideoGen 参数 → 工具适配器内部提交 → 服务任务 ID → 状态轮询 → 产物返回 → 下载 → 文件生成 → 模型收到结果 → 展示。

现有证据只能看到工具边界、完成返回、本地 MP4 和结果进入模型。服务地址、远端任务 ID、下载事件待适配。服务端模型、远端运行环境若不披露，标“服务未提供”；本机网络事件不能证明云端内部实现。

### 读取文档并分析
文件选择 → 技能/接口查询 → 本地打开与结构 → 转换失败 → Python 解析失败/空输出 → 修复 → 正文输出 → 正文进入模型 → 分析结果。

须同时保存外层命令状态、内部业务状态、stdout/stderr、截断标记；pipeline exit 0 不能覆盖内部失败。区分文件打开、结构查询、正文提取、文件上传、正文进入模型。可对比提取文本与源文件，记录覆盖，不将文本提取误称为包含图片/布局的完整文档读取。

本次 doc_to_image 说明存在 COS 上传路径，但调用超时不能证明实际上传。后续采集提交/传输/结果证据分别表达。

## 展示契约

完整链路稳定布局，每一节点展示行动、实际输入输出、资源变化、发现与证据来源。连线明确原生调用关系、内容对应、事后检测或未确认关联。错误、重试、替代路线保留。实时新增与历史回放明显区分。

前端订阅任务提交通知，每批只更新变化的节点。动画取事件投影而非原始流，有限并发、可暂停、减少动态效果；动画省略不会删除证据。界面长时间不用可暂停动画和降低刷新，事实采集继续。

## 验收

三个真实任务分别回放并验证模型—工具—资源—下一次请求的证据链，确认原文可定位且任务不串联。

同一机器比较未采集、基础采集、深度采集的任务耗时、CPU、内存、磁盘写入和队列延迟；分别测采集核心、正文处理、索引、分析、UI。先建立基线再定门槛，不用未测数字承诺性能。

故障测试：高事件速率、巨量输出、文件轮转、进程重启、正文截断、队列满、磁盘满、断网、服务超时、迟到证据。核对掉采情况是否可见、恢复是否重复、后台任务是否影响前台交互。

交付顺序：事件与覆盖契约 → 追加流及内容引用 → 三场景适配 → 原生系统事件关联 → 增量投影 → 动画 → 压力及平台验收。
