# 模型上下文 UI 原型 V2（用户已确认，实施验收基准）

用户已要求严格按照两张原型开发。两张图均使用示例数据，不代表功能已实现。
生成方式：内置 image_gen。提示词要点：AppLens 展示连接、采集、上传与重试状态；
AgentPair 展示模型输入分类及宽幅原文阅读器；不采独立工具事件，不清洗替换原文。

## 冻结的布局

- AppLens：左导航；顶部平台入口、暂停；连接条；三组运行状态；最近调用表；选中调用的上传阶段与说明。
- 平台：左侧直接可见模型数据入口；设备/应用/会话/调用筛选；请求信息条；上下文分类表及右侧完整性；下方宽幅原文及分类依据。
- 配对是首次接入流程，不占用已连接状态下的主界面。
- 平台分类表必须按当前调用筛选；未知内容独立保留，不混入已确认分类。
- 完整已采集原文必须可读、可搜索、可复制，不能用小块 JSON 替代。

## 数据边界

- 只采模型输入，不另采工具执行事件。请求本身包含的上下文按真实原文保留。
- SOUL、IDENTITY、USER、MEMORY、AGENTS 分类必须有明确段落边界或可靠来源；只有提到名字不能声称已拆出文件内容。
- 当前轮输入与历史对话无法可靠划分时显示未分类，不猜测。
- 所有原文仅设备所属账号可见；不在公共任务或游客页面展示。
- 源记录截断、完整性未验证、网络发送未验证要分别表达；不因本地入库就称远端接收。
- 图片中的尺寸、会话名、模型、哈希一致与同步计数均为示例。实现时只有取得真实证据才显示对应结论。
- 未采集字段显示未知/未采集，不能填写示例值或以绿色成功替代。

## 操作验收

1. AppLens 安装后运行的是最新版本，配对后显示绑定的平台与设备状态。
2. 一次真实调用在本机列表与平台列表可相互定位，不要求用户输入 URL。
3. 上传成功以服务端回执及采集原文哈希一致确认；失败可重试，重复上传不产生重复调用。
4. 切换会话/调用后，分类清单、原文、大小、来源和完整性必须同步切换。
5. 选中 USER.md 等类别可阅读实际边界内的内容，并定位回完整输入；无法确认边界的内容不伪装为文件全文。
6. 搜索、复制、导出、暂停、恢复、重试和平台跳转均真实可用。
7. 在真实浏览器中逐项测试并对照两张原型截图；接口测试和构建成功不能替代视觉及交互验收。
8. 有缺口就列未完成；不将局部接通称为整体完成。改变布局或减少能力需先与用户确认。
