# 先回答，再展开依据

本版实现已确认的三个回答场景，共用智能助手入口，不修改采集、原始证据或既有模型配置。

## 入口与问答

- 首屏是大输入框，输入框在答案之前。提问后保留原问题。
- 项目、代码原因、执行过程的快捷问题只发起正常检索，不绑定演示任务。
- 对象不明确时确认任务，不默认展示最近的 SSH、天气或其他任务。
- 回放换步、展开依据与后台采集不能覆盖用户尚未提交的追问。
- 同样的回答和采集状态不重新创建回答控件，保留阅读位置。

## 项目回答

展示真实项目名称、已关联的最近需求、来源和时间。名称和路径不能直接证明业务用途；未分析的用途不补写。

点击项目后展示需求列表；点击需求后进入这次任务的执行过程。目录内容与覆盖范围按需展开，不在主回答堆数量。

项目中的执行回顾与沟通次数追问，先列出该项目实际关联的任务，由用户选择；不自动挑第一项，也不扩大到全局检索。同一追问失败后重试保留项目范围，新主题不继承旧任务。中英文推荐按钮发出的提问与显示文案一致。

## 修改原因回答

先回答用户为什么修改，再展示原始要求、已记录思路和修改涉及的文件。原因来自已有模型回答或记录摘要，明确区分事实、推断和缺失。

需求与反馈、已记录思路、修改文件放在默认收起的依据区域。多轮讨论保留原话和关联理由；任务归属可修正。

写入请求只证明工具调用中出现该路径，不自动证明文件已写入或交付有效。

## 执行过程回答

步骤根据采集到的实际动作生成，不预设每个任务都有四步，也不预设工具名称。

选中一步，只展示该步的可读输入、返回与后续线索。调用与返回用 callId/源关系关联；思路的顺序候选关系明确标注。缺少模型请求证据时，不把动画或时间顺序当作模型接收的证明。

回放支持播放、暂停、下一步和倍速；到最后一步结束，不循环、不重新执行命令。查看原文和切换任务停止回放。

## 视觉约定

背景 `#F7F8FA`，答案白底，边界 `#E6E8EC`，圆角 12。按钮与当前步骤统一蓝色 `#2563EB`。标题、正文和元信息分别设置层级；绿/琥珀/红仅用于结果与核验状态。

桌面界面为原生 Qt，macOS、Windows 共用组件。参数、URL、文件路径与原始返回在对应步骤里核对，原始大记录继续采用有边界的读取。

## 中文与英文

侧栏提供简体中文与 English 切换。设置保存在本机 `settings.json` 的 `ui.language`；没有偏好时按系统语言选择。切换仅改变产品文案，保留输入草稿、选中步骤与已展开的依据。

英文问题通过同一查询服务识别项目、需求和执行过程；统计由本机计算，不由模型猜测。模型解释明确指定回答语言，规划、解释和复核使用同一语言，缓存键包括语言。任务原话、代码与工具返回不自动翻译，避免翻译替换原始证据。

Windows 与 macOS 使用相同代码实现输入、答案、卡片、回放和语言切换。GitHub Actions 在两个操作系统分别运行回归测试、构建原生应用并执行双语打包自检；操作系统字体与窗口外框采用各自的原生样式。

## 验证范围

验证项目进入需求、不同任务切换、缺失证据、多轮用户发言、参数与返回展示、有限回放、草稿保留和空状态。当前会话日志不能认证实际模型 API 调用总数，展示未知；不把用户发言或模型消息标识替代 API 次数。

界面调整不代表检索准确率验收已通过。原型的示例叙述不进入真实回答数据。

项目路径解析只读取工具参数和 Python 调用中的字面量文件参数，不把字符串内的代码示例、样式或模板当成执行路径。文件检查失败不使整次回顾中断；解析升级只分批刷新派生的项目关联，原始采集记录保持不变。
