# 多轮需求与执行关联

以前每条有效用户消息生成一个任务。经过需求讨论、修改和确认后，单独的“做”会成为新任务，随后工具记录只关联到这个短指令。本次增加可重新生成的任务关联层，保留原始事件和原有逐轮索引。

## 数据链路

- `tasks`、`task_steps`：原有逐轮提问与证据；不删除、不改写。
- `task_links`：每轮提问归属哪个任务，关联类型、原始位置和判断依据。
- `task_groups`：面向历史搜索和问答的任务，标题保留起始要求；检索同时使用后续调整。工具正文仍从原索引读取，避免再复制一份。
- `task_step_owners`：有索引的步骤归属；界面、证据包、工具往返使用同一套归属。
- `task_executions`：每个工具调用的原始执行轮、当时的需求版本、确认指令，以及确认前 Agent 最近提出的内容。工具返回按同一来源、会话、调用编号关联，允许跨用户轮次的后台完成。
- `task_link_overrides`：用户在本机修正关联或从某一轮拆分任务；保留原始证据，拒绝跨来源、跨会话或向未来记录建立关联。
- `task_semantic_links`、`task_semantic_cache`：提问时使用已配置模型核对有限前后讨论，按语义判断需求关系；缓存依据模型、接口和上下文版本隔离。

采集时本机判断只作临时关联，不能作为不同用户措辞的完整理解。问答前增加模型语义核对：读取同一 Agent、同一会话中相关任务的有限前后讨论、当前需求和 Agent 方案，判断讨论、调整、选择、执行、切换与恢复。核对会发送有限相邻对话，可能含其他任务；没有后台全历史模型调用。输入最多取起点之前 12 轮、从起点向后 20 轮及长任务末尾 4 轮；用户正文最多 1100 字符，Agent 最近回复最多 600 字符。长任务可能存在上下文缺口，模型必须保留不确定性。

语义结果使用短编号，经过轮次、引用及前后顺序校验后映射回本机原始证据 ID，拒绝虚构身份、未来父节点和歧义强行关联。关联属于推断，不是用户原话或真实因果证明。模型可能误判；人工修正始终优先，保留并支持重新查询。语义拆分后重新检索，避免继续回答旧分组。未确认的前置需求提示补充或人工修正。关联投影按会话原子更新，避免后台采集覆盖新语义结果；旧回答带关联签名，关联变化后提示重新查询。

## 需求版本与确认

原始需求和每次调整均保留原话。执行记录绑定当时的版本，后续调整不会改变更早执行的依据。确认前最后一条 Agent 回复仅是按顺序关联的候选方案，并不证明整个回复或图像都被完整采集、逐项批准。修改要求后不沿用先前的方案确认。

助手证据包包含需求历程与执行关联，所有引用仍指向实际文本片段。最多读取 120 条、文本预算约 9 万字符；长任务优先包含起始要求、最近需求变更、已选工具的执行依据与首尾证据，显式记录未包含及正文截断。界面工具投影最多 800 条，超出时读取首尾各 400 条。这些限制不意味着原始任务完整性得到验证。

## 迁移与性能

迁移增加派生表，不重置原始采集游标、历史投影游标、证据标记、问答和原日志。初始化复制紧凑元信息；随后按会话低速关联，近期和新增记录优先。关联只读逐轮提问、步骤元信息；仅在展开证据、构造问答包时读取原始正文。该关联过程不调用模型、不上传历史。

已有缓存若只解释了被合并的一轮，提示重新查询完整任务。模型回答缓存随新的证据包和缓存版本更新。

## 验证

新增回归覆盖讨论→调整→确认→做→工具往返、后续修改版本隔离、主题切换/恢复、后台返回、重启、缺少起点、长任务证据选取、旧缓存、确认方案冻结、歧义恢复、派生表迁移及人工修正。

本机另在两个真实 Codex 会话的只读派生副本中检查 1081 个逐轮任务、32857 条步骤元信息，验证其中 4 个真实“做”指令可追溯前文和执行关联。该检查未向模型发送数据，也不是全部语义边界的人工验收。另用已配置模型实测 11 轮完全虚构的不同表达，包含“第二个更适合我们”“这回顺眼了，可以动手了”“行，落地”、中途插入天气与恢复需求，11 轮归属符合预设对照。本次模型实测没有发送真实历史。

完整问答另使用 8 轮虚构对话和两次虚构工具往返，最终回答“手机号登录、卡片布局”，把中途天气任务分开，并区分修改之前的邮箱代码与之后的手机号代码。模型明确说明夹具工具没有真实执行。单元与 Qt 回归共 69 项通过。
