# 项目总览：从开发记录到可追溯的项目清单

用户的问题是“WorkBuddy 一共开发了多少项目，叫什么”，不是检索三个相似任务。总览在本机统计，不调用模型猜全局数量，不上传历史正文。

## 第一版产品入口

侧栏增加“项目总览”，分别选择 WorkBuddy 或 Codex。名称 / 目录检索、自动识别项目 / 人工确认项目 / 待确认目录 / 已排除筛选。首屏展示已识别数量和待确认目录数量，不能把所有开发目录伪装成已确认项目数量。包含原创、二开和实验项目，不表示全部交付。

每个条目展示名称、关联任务数、源码文件数、来源目录；详情显示相关任务与最近 100 条写入 / 修改证据。双击任务进入既有历史过程视图，选择修改依据才读取相应原始事件。主列表不堆源码全文。

用户可以确认项目、修正名称、把迁移副本合并到同一项目，或排除测试 / 临时输出目录。修正保存在本地派生库，不修改日志。同一 Agent 内允许合并；跨 Agent 不合并统计，避免将 Codex 修改算入 WorkBuddy。任务数按现有多轮需求关联去重，关联变化后重新计算。

智能助手收到项目清单 / 数量问题，直接展示本机总览快照与入口，不进入单任务 Top-K 检索、不调用中转、不继承上一个天气或视频任务。全局清单使用所问 Agent 的全部已整理历史；回答保留其生成时的快照，打开总览查看最新结果。智能助手不再展示项目筛选下拉框。

项目级查询由产品内的 `local_project_query` 服务完成：根据真实项目名称 / 目录别名定位项目，返回已关联开发任务数、记录中的源码内容目录 / 文件类型、关联任务动作与已记录思路数量、有关联的开发要求、相关任务入口。同名项目 / 跨 Agent 名称冲突要求澄清，未找到项目不使用天气或 SSH 任务替代；“它里面有哪些任务”可沿用上次已确定项目。计数遍历项目全部已关联任务，而不是前 3 次检索结果。内容目录是路径归类，不能当作已验证的业务功能解释。任务数的明确口径仍为有源码修改记录的已关联需求，不宣称涵盖所有讨论和部署任务；工具统计属于这些任务，可能包含跨项目操作。

项目查询结果由 SessionLens 智能助手自己的输入 → 查询服务 → 原生回答展示完成；`--verify-project-query QUESTION OUTPUT` 用同一产品入口作本机验收，可关闭模型回退、保存本机私有结果与截图。无需 Codex 临时 SQL 查询才能获得这些结果。更深入的原因解释和任务问答仍依赖既有知识问答能力，不能把这个结构化查询宣称为完整自由问答。

## 证据口径

- 第一版识别明确 Write / Edit / WriteFile / EditFile 工具的文件路径；源码扩展名与项目清单标记为线索。仅源文件写入 / 修改请求使目录进入清单。
- Read、安装、浏览器仓库引用、记忆目录、仅 README / 文档输出不计入。
- 根目录通过有限的工作目录容器识别，属于候选边界。目录内日志记录过项目清单，或本机该目录存在 Git / 项目清单标记，加上源码修改记录时可作为自动识别项目；其依据明确区分日志记录与当前目录检测。只检查相关根目录标记是否存在，不读取 Git 配置和项目内容，不扫描整机。当前目录检测不能证明历史远程仓库；没有项目标记或用户确认时保留待确认。平台子目录里的构建清单默认作为同一项目的组件，不按 macOS / Android 膨胀计数。
- 相同名称的多个副本转为待确认，不自动合并；不同用户的同名项目不能混为一谈。迁移目录须通过用户合并确认，第一版没有自动 Git 远程身份合并。
- 不将函数体 / 文件正文中的伪造路径当作第二个操作。不执行日志中的命令。
- Shell 内写文件、动态路径、缺失绝对路径、未采集设备和工具失败均是统计边界；不宣称全量项目发现，也不宣称写入请求就是成功交付。
- 现有 `project_context.db` 处理单次任务的知识归属；此能力的 `project_inventory.db` 扫描全历史开发线索。第一版总览的修正不反写单任务知识归属，避免跨项目任务被覆盖。两者不是相互替代的索引。

## 低负载整理

独立 `project_inventory.db` 保存目录、写入证据 ID / 路径、确认与合并、游标，权限 0600。不复制源码，不使用已满的关键词知识库预算。

后台读取既有任务投影的有限字段，每批 250 条、间隔半秒；每轮先处理最多 100 条新任务记录。历史游标只前进到任务投影已完成的历史位置，新记录使用独立游标，不能跳过尚未整理的历史。空闲时不扫描原始日志正文；不写采集数据库，减少写入争抢。UI 读取紧凑派生元信息，详情按需读取单个事件。

## 验收与当前限制

测试覆盖：源码 / 只读 / 文档 / 记忆区别、Agent 隔离、历史与实时双游标、幂等、合并防环、名称修正、排除、多轮任务去重、Windows 路径、正文伪路径、原始证据展示。需验证打包后的入口和后台实际运行。

2026-10-06 本机只读验证：发现 65 个开发目录，结合记录中的项目清单和本机标记自动识别 22 个项目目录，另 43 个待确认；包含相同名称的迁移目录、补丁目录和实验脚本，不把它们直接算成 65 个项目。当前清单不代表最终项目总数，自动语义归并与 Shell 写入解析尚未实现。110 项回归通过；含本地项目数量问答不调用模型，以及从项目准确打开超出最近 100 条的旧任务。

产品问答补充验收：114 项回归通过，新增随机项目名称、项目内容 / 工具 / 任务聚合、后续指代、未找到项目、双 Agent 同名澄清、去掉项目筛选，以及仅有 Swift 构建清单不计为源码项目。已安装的 Intel 应用通过自己的输入 / 发送 / 回答链路，实际回答了 WorkBuddy 项目总数、weblens 和 AgentSpec 两个项目问题；验收禁用了模型回退，结果由 SessionLens 本机查询服务生成，不依赖 Codex 临时分析。
