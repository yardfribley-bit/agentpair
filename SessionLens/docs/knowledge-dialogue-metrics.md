# 知识助手开发：项目、需求、执行与交互统计

日期：2026-10-06。按已确认的 taste 原型实现原生桌面界面，不替换采集器。

## 同一问答入口

项目清单 → 项目中的需求任务 → 一次任务的需求讨论、已记录思路、工具参数与返回。选择任务在智能助手内展开，不跳去旧日志阅读页面。问题保留在输入框；不需要项目筛选下拉框。复杂解释仍使用已有知识问答与已配置模型。

展示实际产品查询结果，不复制原型中的示意任务名或示意执行结果。没有工具返回时标记未知，不把工具请求当作成功交付。

## 三种计数口径

- **需求任务数**：当前需求分组数，不是用户消息数、Git 提交数或 TaskCreate 的调用次数。分组可由初步关联、模型语义核对及用户修正形成。歧义需要核对，不能称所有分组都是正确业务需求。
- **用户发言轮数**：同一分组中原始用户提问去重后计数，包括确认方案和开始执行。Codex 的镜像用户记录不重复计算。查看需求与确认历程能看到原话与关联依据。
- **模型 API 调用次数**：需完整请求级记录认证。SessionLens 当前是会话日志采集，不把工具调用数、回复分片数、SDK 的 usage.requests 或外层 conversationRequestId 当作总调用数；当前显示暂无法确认。

日志中的 providerData.messageId 可以去重形成“模型消息标识数量”，这是可观察的辅助信息，不认证实际 API 调用总数。大记录的元信息统计有读取预算，保留跳过数量，完整原文不删除。

这些统计读取全部已关联的紧凑任务索引，不由大模型对选取的 120 个片段猜总数。项目统计涵盖其已关联需求中的对话，不代表所有未关联或尚未整理的项目活动。

## 多轮关联与升级

“原始需求 → 好的 → 行 → 干”归一个当前需求，用户发言四轮，确认两轮、执行一轮。明确新目标另起需求；没有前置目标的短指令仍待确认。

对现有方案的反馈、引用和省略追问作为初步承接信号，不仅检查句首固定词。明确新目标不吸收进反馈；复杂多主题仍依赖已有语义核对和人工修正，不能把所有同目录修改合成一个需求。

分类器版本单独更新，保留已有分组并排队重新核对，不清空原始记录、历史采集游标、语义核对与用户修正。

## 闪动修复

- 后台阶段改为内部状态，前台只显示已发布的整理结果；状态条固定高度和尺寸策略，不随文案变化撑开界面。
- 答案仅在新问题、新结果或修正关系时重绘，重复刷新保持原有控件与问题。
- 活动页面决定结果区尺寸，隐藏的旧任务回放页面不再撑大当前界面。
- 隐藏的证据窗口不按后台定时器反复重建；可见历史列表只在结构变化时重建，选中内容不因其他任务更新而重绘。
- 参数与原始证据按需展开，大记录使用明确标记的摘录，避免 UI 线程载入巨型 JSON。
- 项目统计查询只读派生库，不修改权限或触发索引迁移，减少与采集的写入争抢。

## 验收

覆盖四轮归一个需求、反馈承接、新目标切换、Codex 镜像去重、消息 ID 去重但不冒充 API 调用次数、项目未选任务时澄清、重复 UI 刷新控件不重建、隐藏窗口不重绘，以及旧任务/项目修正入口。

123 项回归通过。已安装的 Intel 应用通过自己的问答入口重问真实 mem_sec 问题，返回项目需求分组、用户发言及模型次数的可确认范围；测试没有向外部模型发送真实片段。实测还发现旧分组曾把“页面呢”等反馈当成独立目标，已补充承接判断并保留初步关联标识；被忽略的历史摘要不再计为需求任务。正在询问的项目会优先更新最多四个小会话的待处理关系，大会话继续后台处理，原始数据不修改。

未宣称所有历史分组都已正确，复杂多主题仍需语义核对；未宣称 SessionLens 已具备完整网络模型请求计数。
