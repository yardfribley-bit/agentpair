# 任务、项目与仓库关联设计

日期：2026-10-06。补充任务知识问答设计；项目关联与多轮需求归属是两种关系。

## 产品约定

- 任务可以关联一个或多个项目 / 仓库，不要求每个任务都拥有仓库。
- 临时查询、独立文档处理等可以作为独立任务。只有默认工作目录，不能证明任务属于其中的项目。
- 同一仓库中的不同需求仍是不同任务。跨任务共用项目背景，不把整个仓库历史合成一次需求。
- 本地项目可以没有 Git；仓库、项目、工作目录分别记录，不把目录名当作已确认仓库。
- 用户可修正项目关联，也可明确“设为独立任务”；人工选择优先，原始证据保留。

## 证据与职责

1. **目标关联**：日志中的 Git 操作、明确文件操作路径、明确项目字段等指出本次操作针对哪个项目。只证明操作对象 / 意图，不证明操作已完成。
2. **参考关联**：提问或浏览器背景引用了某仓库，可以帮助理解省略表达；参考不等于修改目标。
3. **运行环境**：会话工作目录、默认 Git 状态单独保留，没有针对项目的动作时只作为运行背景。

可读取 Codex 会话头的 `cwd / git`、WorkBuddy 消息的 `cwd / projectPath`、有限工具参数的 `workdir / path / command` 和原始提问的仓库链接。原始日志头仅限已采集记录指向的普通 JSONL 文件，最多读取首行 64 KiB；使用原始文件身份、epoch 与原行内容核对其已采集事件身份，不把后来修改的文件头当成历史证据。不扫描整机目录。文件缺失、会话不符或格式过大时保留缺口。

只有明确操作路径时，才沿路径有限辨认本机 Git 工作树目录；不打开当前 `.git/config` 内容，不运行历史命令。远程地址以已采集元信息、明确 Git 工具返回或用户确认建立，当前目录检测不能倒推当时的远程或分支。历史元信息的分支标记为“日志记录”。SSH 与 HTTPS 的同一远程规范化为相同仓库标识，去除 URL 内凭据、查询参数与片段。

## 数据组织

`project_context.db` 为独立派生库，保存任务关联、会话头缓存及用户修正。

```json
{
  "taskId": "原任务ID",
  "mode": "linked|unlinked|independent",
  "projects": [{
    "id": "仓库规范地址或本机目录标识",
    "name": "项目名称",
    "repository": "去掉凭据的仓库地址或null",
    "root": "有证据的本地根目录或null",
    "role": "target|reference",
    "basis": "recorded|current_filesystem|user_confirmed",
    "evidenceRefs": ["源事件ID"]
  }],
  "workingDirectory": "日志记录的运行目录或null",
  "gaps": ["关联缺口"]
}
```

`unlinked` 表示当前未记录项目关联，不断言任务天然不属于任何项目；`independent` 表示用户明确设为独立任务。不出现“必须绑定仓库才能使用”的流程。

关联生成按单任务读取有限首尾用户轮、工具调用与必要元信息。缓存依赖原始任务版本、关系版本及人工修正。历史后台整理复用现有小批次，UI 线程不读取日志头或工作树元信息。改归属后知识索引、向量和回答缓存必须失效；不修改原始采集游标。

## 检索与问答

- 项目名称、仓库地址及别名进入任务检索资料，保留证据来源；原始任务标题继续独立。
- 用户明确指定项目时限定或核对对应项目；未指定时仍允许全局任务检索。
- 省略项目的追问继承已确认的任务 / 项目范围；不能把前一个项目无条件套到新临时任务。
- 独立任务按原始目标及过程检索，不需要虚构项目。
- 向量输入优先包含项目 / 仓库和原始目标，而不是重复整段标题。项目关联更新后重新生成相应任务向量。
- 项目线索可以帮助找任务，不代表用户授权、实际执行成功或安全结论。

## 界面

任务元信息增加一行“项目 · 仓库”，项目证据可展开；无关联显示“未关联项目”，人工独立显示“独立任务”。多项目按条目展开，避免挤在一行。运行目录作为背景显示，分支区分日志记录与当前检测。

提供“修正项目关联”：设为独立任务，或输入项目名称 / 目录 / 仓库。用户不必填写全部字段。此入口与已有“修正多轮任务关联”分开。

## 验收

1. 同一仓库修改 README 与修改登录逻辑保持不同任务，但共用仓库背景。
2. 默认 cwd 位于仓库的天气查询，仅有 curl 外联时不自动归入该仓库。
3. 明确操作另一个目录时不继承会话默认仓库；跨仓库操作允许两个目标。
4. SSH / HTTPS 仓库远程去重，URL 凭据不进入派生索引或问答。
5. 用户明确独立任务后不被自动关联覆盖；改回项目后缓存更新。
6. 缺失日志头、未知工作目录及大记录可继续使用，展示关联缺口。
7. 新增 / 合并 / 人工修正后的关键词与向量资料更新；原始事件及采集游标不变。

## 第一版实现记录

- 已实现独立项目背景库、有限元信息解析、当前本机工作树目录识别、用户覆盖与还原、项目目录和仓库规范身份。
- 默认仓库项目共享仓库标识；手动命名的子项目拥有独立项目标识并保留同一个 `repositoryId`。未实现自动识别大型 monorepo 的所有子项目。
- 嵌套 JavaScript 调度中的 `exec_command` 字面对象可解析，区分实际属性与命令字符串内同名字段；忽略注释和字符串中的示例调用。变量表达式或复杂动态目录不执行、不猜测。
- 项目背景按每轮两个任务处理，进入关键词资料和向量前缀；向量按项目解析版本、任务版本及人工修正更新。达到词索引大小预算时，项目背景与独立向量库仍可处理。
- UI 增加项目查询范围、项目 / 仓库元信息、修正项目关联入口；临时任务不必填写项目即可查询。项目范围只覆盖当前已识别资料，不代表全部历史已归类。
- 102 项标准库 / Qt 回归通过，覆盖同仓库不同任务、默认仓库下天气查询、跨目录操作、两个仓库、独立任务、手动覆盖、检索范围、向量更新、原始事件 / 游标不变、嵌套命令以及修改过的日志头不被当作历史来源。
- 本机只读样本：README 更新任务识别为 AgentPair 项目及 `https://github.com/yardfribley-bit/agentpair`，项目来源为工具目标目录与工作树目录检测；GitHub 页面仅作为原记录中的仓库参考，并不认证本地工作树的历史远程；上海天气任务不自动关联仓库，运行目录作为环境保留。未发送真实片段到模型。
- 任务工具参数目前只读取有限首尾记录，不宣称列出了长任务的全部项目。当前检索准确率仍需按新资料重新验收，不能复用此前指标宣称已提高。

安装验收补充：打包后发现读取当前 Git 配置会阻塞后台，已取消该额外文件读取，优先使用原始日志中的元信息 / 工具返回，并保留未知状态。新增本机私有后台阶段状态与初始化自检，安装后需要确认任务关联计数确实增长。
