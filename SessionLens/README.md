# SessionLens

独立桌面会话日志采集器，支持 macOS、Windows 上的 Codex 和 WorkBuddy。与 AppLens 同级：SessionLens 读取会话日志，AppLens 负责请求上下文；最终由 AgentPair 处理分析。

## 桌面版

在本目录执行：

```sh
python -m pip install -r requirements-desktop.txt
python desktop_main.py
```

点击“设置并开始采集”，选择 Codex、WorkBuddy 或同时采集；应用自动适配操作系统，不需要平台切换。界面分别展示两个来源的用户提问、Agent 回复、解题思路、工具调用、工具返回、会话背景、用量与状态、暂未识别记录。最近内容有可读摘要，双击查看完整原文、会话 ID、工具 callId、文件位置、字节范围和哈希。

采集过程显示文件读取、历史回填字节进度、本地保存、未确认上报记录、发送状态和平台接收数量。所有数量来自本机数据库，未配置上报时明确显示仅本地采集。关闭应用停止采集；重新打开后通过设置启动，接着上次游标继续读取。

默认读取所有历史文件，不设置时间或文件数量筛选：

- Codex：`~/.codex/sessions`、`~/.codex/archived_sessions` 的 rollout JSONL。
- WorkBuddy：`~/.workbuddy/projects` 的 JSONL；设置中可更改目录。

只有源日志实际提供的 reasoning 才会被采集；这不是隐藏思维链、进程、网络或完整模型输入的拦截器。源文件不存在时文件计数为零，不生成模拟记录。日志格式未知时保留原文并归入暂未识别。

## 存储与上报

macOS：`~/Library/Application Support/SessionLens/collector.db`。
Windows：`%LOCALAPPDATA%\SessionLens\collector.db`。
配置在同目录 `settings.json`，不保存设备令牌。桌面单实例锁防止重复启动；SQLite WAL 保存记录、读取游标和按上报目的地/令牌身份隔离的回执。

任务知识索引独立保存于同目录 `knowledge.db`。后台分批整理任务目标、用户轮次、思路、工具及返回的有限摘录；不复制全量原始正文，不请求模型。默认大小预算 256 MiB，达到预算暂停新增索引并提示，原始采集继续。知识索引可重建，原始证据及游标保留。设计与开发契约见[任务知识问答系统设计](docs/task-knowledge-assistant-design.md)。

不配置接口和令牌，仅本地保存。启用上报需要 AgentPair 登记的设备令牌和 HTTPS 地址，例如：

```text
https://www.chuhaijian.com/api/sessionlens/events
```

启用后发送所选日志的完整记录，不自动脱敏；设置界面明确说明上传范围。采集与上报使用独立线程，失败自动退避；只有平台完整确认这一批事件 ID 后才标记接收。日志目录每 15 秒发现新文件，已发现文件约每 0.5 秒检查增量；每文件单轮读取 200 行，按修改时间优先处理。实际延迟还受日志落盘、历史积压和磁盘性能影响。

单原始记录超过 64 MiB 时保留游标并显示错误；单事件超过上报配额时保留本地、显示数量，并继续上传其他记录，不伪造成功。尚未实现大事件分片上传。工具往返通过 callId 关联，不能仅凭会话日志证明真实系统行为。重复来源记录保留各自证据，不把记录数当作用户操作数。

## 构建与验证

GitHub Actions `.github/workflows/sessionlens-desktop.yml` 在 macOS、Windows 本机 runner 上测试并打包，产物为 macOS `.app` 与 Windows 便携目录（包含 `.exe` 及依赖）。桌面构建尚未签名或公证。

```sh
python -m unittest discover -s tests -v
python desktop_main.py --self-test
python -m PyInstaller --noconfirm --windowed --name SessionLens desktop_main.py
```

原标准库命令 `python -m sessionlens --source 路径 --state runtime/collector.db` 保留用于 Codex 单目录采集；双来源桌面运行使用上面的入口。

## 分析链路

`sessionlens.analyze`、`sessionlens.report_site` 保留已有分析和展示实现。AgentPair SessionStore 接收 Codex、WorkBuddy，校验设备身份、回执和重放一致性；按 callId 组织证据。正式接收接口部署脚本为 `ops/deploy_receiver.py`，复用 AgentPair 设备认证、带备份与回滚。模型分析仍是明确标记覆盖范围的摘录，不是全会话自动分析。会话洞察展示与原始日志上报接口分开授权。

运行数据库、日志、令牌、虚拟环境和构建产物不提交 Git。

### 任务监督与历史追溯

“任务记录与采集设置”提供三栏：任务列表、原始要求与处理经过、对应证据。
监工模式持续更新各会话最近的任务；历史追溯按提问、文件和工具记录中的关键词查找任务，支持 Codex / WorkBuddy 筛选。
点击步骤核对原文、文件来源及字节位置，可以在本机标记待核实并导出完整记录。

任务索引在后台增量建立，首次升级会整理已有历史，原始采集数据不会删除。
大任务分批展开步骤。任务在逐轮原始索引之上关联多轮讨论：明确的调整、确认、“做”与继续执行承接当前需求，每次工具动作保留当时的需求版本。主题切换另建任务，后台返回按原调用关联。关联判断可在本机修正，缺少日志的行为无法补推。详见[多轮需求与执行关联](docs/multi-turn-task-lineage.md)。
“结束状态未记录”与“已记录结束”分别显示；监工展示日志最新动作，不证明 Agent 进程仍在运行。
摘要来自记录摘录，未记录的处理理由不自动生成。采集和上报配置入口位于右上角，未配置接口与令牌时仅本地保存。

监工模式默认跟随最新任务与动作，点击证据可取消跟随，勾选“跟随最新动作”恢复。
普通启动自动开始本地采集，上报仍需明确配置接口与本次令牌。
WorkBuddy 提问从 `user_query` 中提取，系统提醒与历史压缩摘要不作为新任务；工具调用与返回按调用编号成对核对。
历史整理按小批次节流（每次 50 条，批次间等待 0.5 秒），新记录使用独立优先通道；启动先为两种 Agent 预热近期记录。

### 工作记忆助手

首页以对话为入口，无需先选任务。可询问“之前 WorkBuddy 查上海天气遇到了什么问题”，再追问具体工具参数。最近对话保存在本机，引用在右侧打开原始记录；“任务记录与采集设置”保留监工、历史追溯和采集配置。

内置模型使用既有中转的 `deepseek-v4-flash`，界面统一称为助手。模型先理解问题、检索词和关注点，本机使用 SQLite FTS5 / BM25 与可选本地 embedding 混合检索，再由本机配置的 HTTPS 中转模型解释相关证据。索引尚未包含某任务时，可退回只检索需求元信息，不扫描全部历史工具正文。明确指定 WorkBuddy / Codex 时限定来源；追问延续上轮证据。语义相似度只提供候选，缺少明确锚点时需要用户确认；不保证召回所有相关任务。

本地 embedding 使用固定版本的 `Xenova/bge-small-zh-v1.5` 量化 ONNX 模型（源模型 BAAI，MIT），CPU 推理、512 维、CLS pooling 与 L2 归一化。设置中选择模型目录并勾选“启用本机语义检索”。运行时不下载模型、不发送日志给 embedding 服务。模型安装是显式命令：

```sh
python tools/install_embedding_model.py --directory /path/to/models/bge-small-zh-v1.5
```

任务目标向量保存在状态目录 `embeddings.db`，使用 float32 BLOB，默认 64 MiB / 10000 个任务的独立预算，不占用已满的关键词索引预算。后台每批两个任务，间隔一秒，新任务优先；配置或需求改变时按版本重建相关向量，原始记录不变。检索使用同模型身份，精确计算任务向量相似度，与 BM25 候选融合并核对命名实体；文件名不会仅靠语义相似度认定为同一文件。该索引覆盖任务目标，不覆盖全部 reasoning / 工具正文。

项目与仓库关联保存在独立的 `project_context.db`，详见[关联设计](docs/task-project-context.md)。通过已采集会话头、任务元信息与有限工具参数识别操作项目、参考仓库和运行环境。日志头须与本机保存的原始事件哈希对应；本机仅检测 Git 工作树目录，不读取当前 `.git/config` 内容；仓库地址以日志、工具返回或用户确认建立，浏览器参考单独展示，不能倒推历史分支。支持记录内嵌套 `exec_command` 的字面参数解析，不执行历史代码。

侧栏“项目总览”按 WorkBuddy / Codex 分别列出有源码写入、修改记录的项目，保留相关任务和修改依据。结合记录中的项目清单 / 本机项目标记识别目录，未知身份单列待确认；支持更名、确认、迁移副本合并和排除临时目录。项目数量问题在本机直接统计，不经单任务 Top-K 或中转模型猜数。`project_inventory.db` 独立低速增量整理，不复制源码，不占用知识索引预算；只读、安装、记忆和仅文档不计入，Shell 内写文件尚未纳入。识别目录不等于原创或完成交付，当前清单不是最终项目总数。详见[项目总览设计与边界](docs/project-inventory.md)。

智能助手直接接受“WorkBuddy 一共开发了多少项目”“weblens 项目有多少任务，里面有什么”等项目级问题，不需要先选择项目筛选。产品本机查询服务按已关联任务聚合数量、源码内容目录、工具动作和原始需求入口；同名或多 Agent 项目先澄清，选定项目后可追问。当前目录摘要是记录的文件组织，不替代业务功能理解；已关联开发任务不是全项目任务总数。

任务可以没有项目或 Git 仓库。仅有默认工作目录、仓库环境或浏览器背景时，不自动把天气等独立查询绑到项目；明确的仓库 / 文件操作才建立目标关联，用户显式提到的仓库可作为参考。不同需求共享项目背景，但不合并成同一个任务。手动命名的子项目可共享仓库身份。

助手可选择“全部任务 / 未关联项目 / 已识别项目”范围，任务详情显示项目与仓库，并提供“修正项目关联”：关联到项目、设为独立任务、恢复自动判断。未指定项目时仍全局查询。用户修改后只更新派生知识归属与相关向量，原始证据保留；旧解释提示重新查询。历史关联按小批次整理，不能把尚未整理或未采样的项目操作断言为不存在。

`tools/evaluate_embedding.py` 用标注任务 ID 的题集评估 Top-1、Hit@5、MRR 和错误自动选择，区分开发题与验证题。2026-10-06 本机 5069 个真实历史目标、27 道人工题的目标索引对照：混合检索 Top-1 59.3%、Hit@5 77.8%，错误自动选择 0；BM25 对照分别为 33.3%、37.0%、2。当前准确率验收未通过，不代表大模型回答正确率或全历史采集完整性。反复使用的验证题也不视为独立未见测试集。真实历史未送到中转；仅人工题目用于现有模型的检索意图理解。

工具 / 网址 / 返回等问题优先读取相关记录，包括长任务中间的具体调用，并补齐对应返回和执行前依据。每次回答仍有 120 条 / 约 9 万字符预算；大原始记录使用明确标记的索引摘录，完整正文仍可查看。多任务问题最多比较 3 个检索到的任务，各条证据保留所属任务与独立编号；可以进入其中一次任务继续追问。多任务之后省略指代不清时要求选择，不默认指向第一项。知识整理进度在助手底部与采集状态中展示。当前比较基于已有任务投影，归属不准时仍需修正。

检索包含原始需求及后续调整，不把“做”作为新的独立目标。采集阶段先在本机作临时关联；提问时再调用已配置模型，结合相关任务的有限前后讨论和 Agent 方案核对需求归属，支持不同措辞、方案选择、插入任务和恢复。核对还包含有限的已记录 reasoning、工具动作和源消息父子关系；这些只辅助判断，不能沿父消息链把全部聊天归成最早的需求。需求归属核对会发送同一会话的有限前后文摘录，可能包含相邻任务；不同 Agent / 会话的记录不会混入。模型判断保留依据、可人工修正；不确定时提示确认。回答界面可展开需求与确认历程，核对每次执行的需求版本及确认前 Agent 最近提出的内容。升级在后台处理原有逐轮索引，不调用模型批量发送全部历史。

检索同时使用用户原话和模型改写，切换任务时重新绑定对应证据。已有对话在匹配程度相同的情况下优先延续正在讨论的 Agent；新对话遇到不同 Agent 的同名任务时，展示来源和日期供用户选择。追问仅参考当前任务的问答，新查询等待期间不展示上一项任务的回答。重新打开旧对话时，发现任务绑定明显不符会提示重新查询，保留问题与原始数据。

任务匹配提取主体名称和原任务动作，完整文件名不与相似文件名混用；来源名称不作为主题匹配词。长引用文本不能靠词数压过任务本身，历史摘要与后台通知不作为新任务。省略主语的追问优先绑定当前任务；明确的新主题仍可切换。未指定另一个 Agent 时，先检索正在讨论的 Agent，找不到相关任务再扩大范围；明确指定的来源始终生效。相近候选需用户确认，不存在的主题或没有上下文的“那个任务”会提示补充信息，不用无关任务代答。未解决的查询会中断追问绑定，避免跳回更早的任务。

模型回答在保存与展示前进行证据复核，检查概述、引用和缺失说明是否一致；缺少调用记录不等于证明从未执行。复核不能替代真实系统验证，也不能保证模型不会犯错。旧版本回答缓存不再复用，原始任务和对话仍保留。

回答区分记录事实、推断和记录缺失，每段可核对引用。最多选取 120 条证据，长记录和大任务按预算截取；原始日志不修改。整理尚未完成的历史可能暂时检索不到。模型只能解释日志提供的信息，不能证明未记录的行为或原因。

提问与少量对话背景用于检索意图理解，选中的证据摘录用于回答；原始日志批量上报仍是独立配置。分析结果缓存于 `assistant.db`，对话保存于 `conversations.db`。同一证据版本与问题复用缓存。

`ops/deploy_assistant.py` 部署私有 HTTPS 网关。该网关用于原有服务端分析。桌面助手在设置中单独配置模型地址、模型名与凭据文件（JSON 的 apiKey 字段）；凭据保存在本机私有文件，不纳入源码。调用中转仍是外部推理，不是离线模型。

### 任务解释与历史思路回放

大输入框下展示对应的单次任务和直接回答，提供过程、思路、工具、上下文、交付验证五个视图。思路支持逐字回放、暂停、速度调整和原文；后续动作按日志顺序展示，工具与返回按 callId 关联。参数解释与原始 JSON 分层显示，命令中的完整网址及查询参数保留。结果只解释记录，不执行历史命令或重新验证交付物。

桌面任务展示按 SSH 原型组织：一处页面滚动，短回答、脑图思路摘录和动作→返回→调整卡片；工具参数用字段展示，原始日志默认收起。播放只更新摘录和高亮，不重建页面或改变滚动位置。上下文和交付视图收起播放器。

新版首屏显示简短结果与已交付/未核验状态，横向步骤条按实际工具记录生成；提示词准备由已记录输入参数分拆展示，不视为额外调用。点击步骤只展开当前步骤，五个视图作为回放面板内的分段控件。元信息合并为一行，原始思路与参数默认收起。
