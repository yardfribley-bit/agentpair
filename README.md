# AgentPair

**让两个 AI 分工执行与复核，在同一任务中协作交付结果。**

AgentPair 是一个以结队编程为核心的双 Agent 协作框架，提供任务发布、多轮对话、工具调用和过程可视化。你描述目标，Driver 负责实现或查询，Navigator 负责规划、核查与决定是否返工。它的目标是减少未经验证的结论，让用户看见结果来自哪里、为什么被接受，以及还有什么没有完成。

> 当前为实验版本：已具备真实天气查询、代码建议复核及有限网站取证。代码执行、自动测试和自动提交尚未接入；尚无评测证明双 Agent 比单 Agent 更准确。

## 可以用它做什么

| 使用场景 | 可以发布的任务 | 当前能交付什么 |
| --- | --- | --- |
| 结队编程与代码讨论 | “实现支持列表和字典的稳定去重函数，检查边界条件和复杂度。” | 代码建议、复核意见与多轮修改；不运行生成代码或测试 |
| 查询与事实核查 | “查上海现在的天气，告诉我数据时间和来源。” | Driver 查询天气接口，Navigator 复核；保留原始数值、时间和来源 |
| 持续完善方案 | “在上一轮方案中增加错误处理，并解释取舍。” | 保留任务上下文的方案修订与复核记录 |
| 有限公开网站分析 | “检查这个公网 IPv4 网站公开页面的技术线索。” | 公开页面、有限资源、注册和路由信息；当前需通过 API 指定类型和目标 |

天气目前使用 Open-Meteo 模型估算，并非气象站实况观测。通用网络搜索、任意网站浏览和多源自动核验尚未实现。网站分析是工具示例，AgentPair 的核心是可复用的执行与复核机制。

## 从发布任务到获得结果

进入已部署的 Web 工作台，点击 **发布新任务**，填写标题与要求。用户无需选择内部“任务适配器”。

发布时可选择工程方法：默认协作不创建云机器；云端结对占用最多一台 Driver；并行方案探索占用两台独立 Driver，分别探索不同路线，由常驻 Navigator 比较并综合。界面会说明每种方法的优势、适用场景、参考云机费用和模型调用数量。已有可用租约优先复用，任务结束不立即释放。工程方法保存后沿用于该任务的后续轮次；未选择时，模型无权自行开机。当前 Driver 仍提供查询与代码建议，尚不执行生成代码或测试。

并行模式现在分三段：A/B 各自探索、交换带来源的发现并交叉复核、接收对方意见后修订。Navigator 最后检查两条修订结果。共享发生在阶段边界，任务事件会记录发送方、接收方、证据编号和待核查点；尚无工作过程中的实时消息流。

建议同时写清目标和验收条件：

```text
用 Python 实现 stable_unique，保持输入顺序，支持列表和字典。
给出实现、边界用例和复杂度分析。
检查代码与要求是否一致，明确哪些测试尚未执行。
```

提交后，工作台显示规划、Driver 处理、复核和最终状态。你可以展开对话与证据、查看角色交接、导出记录，或在同一任务中追加要求。

**已完成**表示通过当前验收规则；**未完成**表示存在证据或能力缺口；**失败**表示运行出错。动画由真实阶段事件驱动，每两秒同步。

## 两个角色怎样协作

| 角色 | 工作 | 输出 |
| --- | --- | --- |
| Navigator | 理解要求、制定计划、逐项验收、决定补查或交付 | 计划、验收依据、返工要求 |
| Driver | 根据计划生成实现建议或调用已接入工具 | 答复、代码建议、原始工具证据 |

默认协作每轮先 **规划 → 执行 → 复核**；验收提出可执行补正时最多再整改两轮。并行模式每次 Driver 阶段由 A/B 各执行探索、交叉复核和修订，共六次 Driver 调用；用户继续发消息时开启下一轮。

Navigator 借鉴 Jev 的结构化决策思想，分别判断目标是否满足、依据是否充分、结果是否一致。每项返回 yes、no 或 unknown 和理由，程序据此选择交付、补查或需要补充信息。天气任务另有数值、单位和时间检查。

已接入 TypeSafe 官方开源 System One Adapter，使用现有中转的 `deepseek-v4-flash` 执行规划判断和独立验收。运行的是 DeepSeek，并非 Jev 本体；模型自报概率不作为准确率。详见 [决策机制](DECISIONS.md)。

## 当前实现范围

- Web 任务发布、多轮对话、协作状态、结果与验收依据展示。
- SQLite 持久化、队列、任务历史隔离、取消和记录导出。
- Navigator 负责规划和复核；Driver 默认在同节点运行，用户选择云端工程方法时按需分配一台或两台 UCloud Driver，经 SSH 调用。
- 真实工具查询、来源记录，以及最多两轮复核返工。
- 默认实验限制：20 个任务、每任务 3 轮；普通任务每轮最长 10 分钟，并行协作每轮最长 30 分钟。

尚未提供隔离代码执行器、测试驱动修复、自动 Git 提交或生产级多用户管理。两个角色当前使用同一模型，复核并不保证独立性。

## 本地验证

使用 Python 3.10 或以上版本，无需第三方 Python 包：

```sh
git clone https://github.com/yardfribley-bit/agentpair.git
cd agentpair
python3 -m unittest discover -v
python3 -m agentpair.demo
```

测试不依赖付费模型调用。`agentpair.demo` 是离线模拟，不能作为真实工具执行或代码测试成功的证明。

真实工作台需要模型服务凭据；云端 Driver 另需 UCloud 项目、API 权限、独立防火墙和 SSH 配置，参见 [部署与运行](PLATFORM.md)及[资源控制](RESOURCE_CONTROL.md)。部署脚本针对本次指定服务器，并非通用一键安装器。

## 部署、费用与数据

本次持续运行的 Navigator 工作台位于 [https://50.118.187.180/](https://50.118.187.180/)。访客可直接查看任务与实时协作过程；管理员通过右上角登录后可发布、追加和停止任务。服务端验证所有写操作的权限。

当前工作台未设置模型总金额上限；显示的费用是历史价格估算，不是供应商账单。只有用户选择云端工程方法才允许按需开机，并受一小时租约、并发数和云主机报价上限约束。云资源费用与模型费用分别计费。

任务内容会发送到配置的模型服务。凭据在服务器受限配置文件中，模型上下文不含 UCloud 密钥；数据库、密钥和运行记录不纳入 Git。云 Driver 到期由独立定时器回收。持续运行的 Navigator 仍需备份和运维监测。

## GitHub 源码阅读

任务中给出公开 GitHub 仓库地址、分支或提交以及重点文件，Navigator 可调用
`github_repository`，通过 GitHub API 获取不可变提交快照，再用开源
[GitIngest](https://github.com/coderamp-labs/gitingest) 在本机整理上下文。
Driver 和 Navigator 复核共享同一份带行号的源码；证据包含提交 SHA、文件路径、
永久链接和未读取文件。仓库内容不作为系统指令，不执行仓库脚本或子模块。

目前每次最多读取 8 个指定文件、100 KB UTF-8 源码；目录索引最多 500 项。
不支持私有仓库、任意网页搜索、自动修改仓库或运行构建。没有读到的文件不能作为
已验证依据。此能力不等同于完整 IDE 或自主编程执行器。

依赖：`pip install -r requirements-repository.txt`。源码只发送到当前配置的模型端点，
不上传 GitIngest 托管网站。常规输出最多 6000 tokens，截断时最多一次 12000-token
重试，两次调用消耗累计展示；仍截断则明确失败。

## 隔离代码执行（实验性）

发布任务时显式选择「云端结对」和 Python/Node 执行环境才会申请 Driver；默认仍不创建机器。
Navigator 不执行仓库代码。Driver 获取固定公开提交、应用模型生成的文件修改，
然后在无网络、无特权、只读根文件系统的 Docker 容器中运行固定构建/测试命令。
容器使用 256 MB 临时工作区，输入只读，不挂载 Docker socket、模型密钥或云凭据；
限制为 1 CPU、512 MB 内存、128 进程、每条命令 120 秒。任务记录提供补丁下载和有界日志。

Python 使用 compileall/unittest（零测试不算通过）；Node 使用 npm build/test。
当前不会在线安装项目依赖，不导出二进制构建包，不自动推送 GitHub；依赖缺失明确失败。
这些是已接入但尚待真实云机端到端验收的实验流程，不应视为生产沙箱安全认证。
云机保留到原租约结束以便复用，不因单次验证完成而立即删除。

## 网页助手（实验性）

独立 Driver 复用 WebLens 已有的 Lightpanda 客户端实现，对外提供 AgentPair 浏览器工具，
支持真实页面读取、工具事件回传、文本文件交付与 Navigator 复核。不是部署 WebLens 产品。
选择云端结对与网页助手，并在需求中给出完整 URL；默认协作不创建机器。
实现边界、部署前提和缺口见 [浏览器整合说明](BROWSER_INTEGRATION.md)。

## Android 手机协助（实验性）

Android 客户端可配对到账号、定时上报在线心跳、接收云端下发的设备任务，并把接收/执行/结果状态回传到网页工作台。任务只展示给用户，由用户确认并填写文本回执；客户端不执行任意命令或应用操作。另有短时验证码转交接口供后续集成：对当前任意第三方短信场景，用户需在手机上手动输入并确认验证码；验证码只通过设备认证通道提交，三分钟有效、一次消费，不写入任务消息/记录，也不发送给模型。浏览器执行器尚未连接验证码消费接口，因此不代表自动登录或自动发文已经实现。

普通应用不能假设可静默读取任何短信：Android 将 `RECEIVE_SMS` 设为 hard-restricted；Google Play 对 SMS 权限要求默认短信/Assistant 角色或符合政策例外。SMS Retriever 自动读取需要目标网站配合短信模板。故本客户端不申请短信权限；自动读取是后续有网站合作或合规产品形态后再做的能力。

Android APK 使用本地 Android SDK 构建：`python3 android/build.py`。构建后会写入 `agentpair/web_assets/AgentPair-Android-0.1.0.apk`，由「我的设备」下载路由提供。当前为开发签名测试包，尚未上架，也未做真实手机/FreeBuf 登录验收。
