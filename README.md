# AgentPair

**让两个 AI 分工执行与复核，在同一任务中协作交付结果。**

AgentPair 是一个以结队编程为核心的双 Agent 协作框架，提供任务发布、多轮对话、工具调用和过程可视化。你描述目标，Driver 负责实现或查询，Navigator 负责规划、核查与决定是否返工。它的目标是减少未经验证的结论，让用户看见结果来自哪里、为什么被接受，以及还有什么没有完成。

> 当前为实验版本：已具备真实天气查询、代码建议复核及有限网站取证。代码执行、自动测试和自动提交尚未接入；尚无评测证明双 Agent 比单 Agent 更准确。

## 可以用它做什么

| 使用场景 | 可以发布的任务 | 当前能交付什么 |
| --- | --- | --- |
| 结队编程与代码讨论 | “实现支持列表和字典的稳定去重函数，检查边界条件和复杂度。” | 代码建议、复核意见与多轮修改；不运行生成代码或测试 |
| 查询与事实核查 | “查上海现在的天气，告诉我数据时间和来源。” | Driver 查询天气接口，Navigator 复核；保留原始数值、时间和来源 |
| 持续完善方案 | “在上一轮方案中增加错误处理，并解释取舍。” | 保留任务上下文的方案修订与复核记录 |
| 有限公开网站分析 | “检查这个公网 IPv4 网站公开页面的技术线索。” | 公开页面、有限资源、注册和路由信息；当前需通过 API 指定类型和目标 |

天气目前使用 Open-Meteo 模型估算，并非气象站实况观测。通用网络搜索、任意网站浏览和多源自动核验尚未实现。网站分析是工具示例，AgentPair 的核心是可复用的执行与复核机制。

## 从发布任务到获得结果

进入已部署的 Web 工作台，点击 **发布新任务**，填写标题与要求。用户无需选择内部“任务适配器”。

建议同时写清目标和验收条件：

```text
用 Python 实现 stable_unique，保持输入顺序，支持列表和字典。
给出实现、边界用例和复杂度分析。
检查代码与要求是否一致，明确哪些测试尚未执行。
```

提交后，工作台显示规划、Driver 处理、复核和最终状态。你可以展开对话与证据、查看角色交接、导出记录，或在同一任务中追加要求。

**已完成**表示通过当前验收规则；**未完成**表示存在证据或能力缺口；**失败**表示运行出错。动画由真实阶段事件驱动，每两秒同步。

## 两个角色怎样协作

| 角色 | 工作 | 输出 |
| --- | --- | --- |
| Navigator | 理解要求、制定计划、逐项验收、决定补查或交付 | 计划、验收依据、返工要求 |
| Driver | 根据计划生成实现建议或调用已接入工具 | 答复、代码建议、原始工具证据 |

一个轮次通常包含三次角色调用：**规划 → 执行 → 复核**。复核要求补查时，Driver 和 Navigator 再执行一次，最多五次调用。用户继续发消息时开启下一轮。

Navigator 借鉴 Jev 的结构化决策思想，分别判断目标是否满足、依据是否充分、结果是否一致。每项返回 yes、no 或 unknown 和理由，程序据此选择交付、补查或需要补充信息。天气任务另有数值、单位和时间检查。

已接入 TypeSafe 官方开源 System One Adapter，使用现有中转的 `deepseek-v4-flash` 执行规划判断和独立验收。运行的是 DeepSeek，并非 Jev 本体；模型自报概率不作为准确率。详见 [决策机制](DECISIONS.md)。

## 当前实现范围

- Web 任务发布、多轮对话、协作状态、结果与验收依据展示。
- SQLite 持久化、队列、任务历史隔离、取消和记录导出。
- Navigator 负责规划和复核；Driver 默认在同节点运行，明确需要独立云端节点时按需创建一台 UCloud Driver，经 SSH 调用。
- 真实工具查询、来源记录，以及最多一次复核返工。
- 默认实验限制：20 个任务、每任务 3 轮、每轮最长 10 分钟。

尚未提供隔离代码执行器、测试驱动修复、自动 Git 提交或生产级多用户管理。两个角色当前使用同一模型，复核并不保证独立性。

## 本地验证

使用 Python 3.10 或以上版本，无需第三方 Python 包：

```sh
git clone https://github.com/yardfribley-bit/agentpair.git
cd agentpair
python3 -m unittest discover -v
python3 -m agentpair.demo
```

测试不依赖付费模型调用。`agentpair.demo` 是离线模拟，不能作为真实工具执行或代码测试成功的证明。

真实工作台需要模型服务凭据；云端 Driver 另需 UCloud 项目、API 权限、独立防火墙和 SSH 配置，参见 [部署与运行](PLATFORM.md)及[资源控制](RESOURCE_CONTROL.md)。部署脚本针对本次指定服务器，并非通用一键安装器。

## 部署、费用与数据

本次持续运行的 Navigator 工作台位于 [https://50.118.187.180/](https://50.118.187.180/)。访客可直接查看任务与实时协作过程；管理员通过右上角登录后可发布、追加和停止任务。服务端验证所有写操作的权限。

当前工作台未设置模型总金额上限；显示的费用是历史价格估算，不是供应商账单。普通任务不创建云主机；规划明确选用 `cloud_driver` 时才按需创建，并受一小时租约、并发数和云主机报价上限约束。云资源费用与模型费用分别计费。

任务内容会发送到配置的模型服务。凭据在服务器受限配置文件中，模型上下文不含 UCloud 密钥；数据库、密钥和运行记录不纳入 Git。云 Driver 到期由独立定时器回收。持续运行的 Navigator 仍需备份和运维监测。
