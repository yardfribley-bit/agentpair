# AgentPair

Agent 结对编程范例：Navigator 负责规划与修复决策，Driver 负责编码，执行器运行固定测试并反馈真实结果。任务可以替换，云资源只是运行载体。

详细方案见 [设计文档](DESIGN.md)。

## 框架优先：下一轮范围

AgentPair 是核心框架；网站分析只是可替换的示例任务。不接入 AgentReins 审计。下一轮计划于 2026-09-30 开发以下三项，目前尚未实现：

1. 深入公开取证：JS、公开接口线索及产品指纹，保留原始证据引用与不确定性。
2. 情报关联：ASN、关联域名、历史记录与威胁情报，记录来源和时间。付费情报 API 需另行配置及确认预算；没有查询结果不等于安全。
3. 多轮验证：Navigator 根据证据缺口安排 Driver 补查，再交叉复核；按轮数、预算、截止时间停止。

框架层负责角色协议、消息转发、状态机、轮次与预算、运行记录和 Web 过程展示。任务适配器负责输入、可用工具、证据格式及验收规则；目标 IP、情报供应商和网站指纹不应固化进核心。

当前网站实验是独立的固定工具链，尚未接入通用协调器进行动态工具选择、多轮补查。现有 IP 和 UCloud 配置是实验脚本的限定范围，不是框架契约。下一轮先打通 TaskAdapter 与通用协调器，再增加网站取证能力。

## 运行当前离线范例

```sh
cd AgentPair
python3 -m agentpair.demo
python3 -m unittest -v
```

当前范例使用假模型与脚本化测试反馈，只验证协调流程，不执行生成代码、不调用付费模型。成功状态明确为 `simulated_pass`，不是实际测试通过。已实现状态机、消息校验、修复与换方案、轮数/请求数/截止时间/取消控制；人民币预算、隔离执行器及真实模型适配尚未实现。

## 双节点网站取证实验

新增 `site_probe.py` 与 `site_worker.py`，通过固定、低频公开取证工具演示 Navigator 规划、Driver 取证分析、Navigator 复核。它是分析任务适配器，不是生成任意代码并执行的完整编程引擎。

`run_cloud_site_pair.py` 是本次指定 UCloud 项目与目标网站的实验脚本，依赖本机临时 SSH 公钥路径；不是开箱即用的通用部署工具。凭据以隐藏输入获取，不写入运行记录。两台报价0.30元/小时，完成或异常时尝试清理并复查；本机 watchdog 不是独立于本机故障的云端清理保证。模型费用按历史账单估算，不是供应商人民币硬限额。

首次部署尝试被 UCloud 余额不足拒绝；充值后已完成两台 Linux 的 SSH 部署及规划、公开取证分析、复核三轮真实模型调用。两个角色均使用 deepseek-v3.2，结果通过本地协调器交换，尚非直接对等通信。记录在本机私密 `runs/` 目录，默认不进入版本控制。

## Navigator 可视化

```sh
python3 -m agentpair.web --run-dir runs/运行ID --port 8080
```

工作台展示节点、候选方案、证据、Driver 结论及 Navigator 修改点，每5秒刷新产物。时间是产物写入时间，不是实时 token 流。默认只监听本机；公网部署需显式指定 `--bind 0.0.0.0`。

当前只支持指定公开网站实验的白名单字段，不提供原始运行目录、云密钥、令牌或任何写入/执行接口。这是公开信息的无登录只读演示，不可直接用于企业审计原文。企业使用前需要 HTTPS、身份认证、授权、数据脱敏与访问审计。

## 实验目标

1. 先验证需求、候选方案、编码、真实测试、修复或换方案的完整闭环。
2. 用可替换的任务描述、输入输出契约和固定验收测试驱动同一套程序。
3. 保留每轮方案、代码版本、测试反馈、调用用量与停止原因。
4. 本地跑通后再部署云节点；弹性资源、审计管理端集成不在第一版范围内。

## 最小协作协议

- Navigator：提出至少两个候选方案并选择一个；读到实际测试失败后，给出修复策略或选择剩余方案。不能自己宣布代码通过测试。
- Driver：根据方案产生代码或补丁；不改固定验收测试，不靠虚构执行日志报告成功。
- Executor：在隔离环境执行代码和固定测试，返回成功、答案错误、运行错误或超时。它是程序，不是第三个 Agent。
- Coordinator：转发上下文、保存历史、执行轮数和费用限制。第一版是小程序，不增加一个规划 Agent。

流程：需求和测试 → Navigator 提案并选方案 → Driver 编码 → Executor 测试 → Navigator 根据反馈修复或换方案 → Driver 修改 → 再测试。

第一版最多三轮实施、两个候选方案。代码或失败反馈重复时触发换方案；测试通过、方案耗尽、预算不足、超时或达到轮数时停止。输出必须区分“测试通过”和“未通过”，不能在达到上限后把最后一份代码当作成功。

参考用户提供的 PairCoder 论文核心工作流；第一版不实现论文中的 embedding 聚类与大规模计划采样，不宣称完整复现或取得论文中的实验效果。

## 第一版交付标准

一个无私密数据的小型 Python 示例任务，完整跑出方案、生成代码、实际测试和最终结果。正常通过、失败修复、重复失败换方案、轮数用尽等路径都须有自动化测试。示例验收不需要访问企业审计服务器，不启动云资源；真实模型调用与生成代码执行前单独核对费用和执行隔离。

## 配置约定

云厂商密钥、模型令牌与登录密码不写入源码或版本控制。使用运行时环境变量或独立的私密配置。每次付费实验需明确数量、配置、预算和清理方式。
